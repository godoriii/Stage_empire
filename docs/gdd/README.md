# GDD (시스템별 상세 설계)

game-designer가 쓴다. 파일 하나가 시스템 하나. 티켓은 여기의 절을 가리킨다.

| 파일 | 시스템 | 상태 |
|---|---|---|
| `events.md` | 이벤트 버스 이벤트 이름·페이로드 (sim/view 공용 계약) | 골격 |
| `tick.md` | 틱, 세션 구간(낮/저녁/공연/마감), 배속 | 미작성 |
| `economy.md` | 수익·비용·파산·구제 | 미작성 |
| `build.md` | 그리드, 배치 규칙, 설비 반경, 커버리지 | 미작성 |
| `artist.md` | 아티스트 성장 경로, 관계, 라이더 | 미작성 |
| `show.md` | 공연 만족도 공식, 사고 이벤트 | 미작성 |
| `audience.md` | 관객 에이전트 상태 기계, 취향, 흐름장 전환 | 미작성 |
| `reputation.md` | 장르별 명성 벡터, 티어 해금 | 미작성 |
| `staff.md` | 스태프 직군, 숙련·피로, 구역 배정 | 미작성 |
| `events_crisis.md` | 날씨·고장·노쇼·민원·사고·바이럴 | 미작성 |

각 문서의 절 형식: 목적 → 규칙(입력/출력/공식) → 수치표(또는 `project/data/` 테이블 링크) → 수용 기준 → 테스트 방법 → 열린 질문.

PRD에서 이미 결정된 값(티어 해금 조건, 8장르, 10 tick/초 등)은 `project/data/`에 들어 있다. 바꾸려면 ADR.
