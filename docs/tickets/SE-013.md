## 목표

프로덕트 오너 결정("관객 군중은 그림자를 드리우지 않는다. 그림자는 무대·가구·스태프만")을 SE-003 스파이크 씬에 반영한 **구성 E** 를 만들고,
그 E 로 ADR-0001 재측정을 할 수 있는 상태로 만든다. SE-003 리뷰에서 나온 측정 도구 결함 4건(진입점 방향, 덕타이핑, GPU 타이밍 가용 여부, 단축 실행 무효 처리)과
`-dirty` 해시 오탐을 같이 고쳐 다음 측정 JSON 이 자기 설명적이고 유효성 판정이 자동이 되게 한다.
실측(사람 PC 1회)에서 E 가 기준 기기 관문(dGPU ≥ 60fps 또는 M1/Iris Xe 급 ≥ 30fps)을 넘으면 ADR-0001 의 조건부 결정이 닫힌다.
넘지 못하면 이 티켓은 결론을 내리지 않고 숫자만 남긴다(Unity 재검토 ADR 은 producer·사람).

셰도우 라이트 8개는 **그대로 둔다**. 군중만 그림자를 안 드리우면 셰도우 패스가 완전히 비어 "측정이 쉬워지는" 왜곡이 생기므로, 무대 프록시(박스) 몇 개를 셰도우 캐스터로 씬에 넣어 라이트가 실제로 그림자 패스를 돌게 한다.

## 범위

- 포함:
  - **구성 E** — `project/view/perf/spike_configs.tres` 에 구성 E 추가: B 와 같은 5,000 / 32 / 셰도우 8 / 아틀라스 2048 에 군중 그림자만 off. `SpikeConfig` 에 `crowd_shadows: bool`(기본 `true`) 필드 추가, A~D 는 값 불변(`true`). `gate_config_id` 를 `"E"` 로, `gate_min_avg_fps` 60 유지. B 는 비교용으로 남긴다(`note` 갱신: "비교용(군중 그림자 on)").
  - **군중 `cast_shadow`** — `spike_crowd.gd::_build_crowd()` 가 `config.crowd_shadows` 에 따라 `crowd.cast_shadow` 를 `SHADOW_CASTING_SETTING_ON/OFF` 로 설정.
  - **무대 프록시 셰도우 캐스터** — `spike_crowd.tscn` 에 `StageProps`(Node3D) 아래 `MeshInstance3D`(BoxMesh) N개. 개수·크기·높이는 `spike_configs.tres`(`stage_prop_count`, `stage_prop_size_m`(Vector3), 배치 비율)에서 읽고 코드에 리터럴을 두지 않는다. 모든 구성(A~E)에서 동일하게 존재해 A~D 의 비교 가능성을 유지한다(A~D 의 primitives 는 프록시 삼각형만큼만 늘어난다. 결과 표에 그 차이를 한 줄 적는다). 프록시는 군중 영역 안, 라이트 높이보다 낮게, 최대 줌아웃 프러스텀 안에 둔다. 합계 삼각형 ≤ 1,000(군중 3.54M 대비 무시 가능).
  - **측정 진입점 뒤집기**(리뷰 발견 1) — 새 씬 `project/tests/view/perf/measure_spike.tscn`(루트 스크립트 `measure_spike.gd` 또는 작은 러너)이 `spike_crowd.tscn` 을 인스턴스화하고 측정기를 붙인다. 루트에 `@export config_id: String` 을 둬 테스트가 명령줄 없이 구성을 고른다(비어 있으면 `--config=`, 그다음 `default_config_id`). `spike_crowd.gd` 에서 `MEASURE_SCRIPT_PATH`, `ARG_MEASURE`, `--measure` 인자 해석, `_start_measure()` 를 제거한다. `measure_mode` 는 측정기가 직접 `true` 로 세팅하는 속성으로 남겨도 된다(입력 무시·라벨 표시용). `res://tests/` 문자열이 `project/view/**`·`project/ui/**` 에 0건.
  - **덕타이핑 제거**(리뷰 발견 2) — `measure_spike.gd` 의 `_spike` 를 `SpikeCrowd` 타입으로, `setup(spike: SpikeCrowd, ...)`, `.get("last_advance_usec")`·`.call("get_*")` 을 직접 호출로.
  - **GPU 타이밍 가용 여부**(리뷰 발견 3) — JSON 에 `gpu_timing_available: bool`(= `avg_gpu_ms > 0`)과 `gpu_timing_note: String`(가용이면 빈 문자열, 아니면 "GPU 타임스탬프 없음 (rendering_driver=<이름>)" 처럼 드라이버 이름 포함) 추가. `bound_hint == "unknown"` 의 이유가 JSON 안에 남는다. 측정 조건 위반(`run_issues`)으로는 잡지 않는다(Metal 에서는 정상 측정이면서 GPU 시간만 없다).
  - **단축 실행 무효 처리**(리뷰 발견 4) — `run_issues()` 가 `warmup_sec < settings.warmup_sec`, `warmup_frames < settings.warmup_min_frames`, `measure_sec < settings.measure_sec` 를 각각 한 건씩 위반으로 잡는다(`--warmup-sec=`/`--measure-sec=` 단축 실행은 자동으로 `run_valid=false`, 관문 "무효"). 서명은 바꿔도 된다(예: `run_issues(stats, env, monitors, settings)`). 기존 4 케이스(샘플 없음·헤드리스·VSync·렌더러·해상도)는 유지.

  - **경계 테스트 추가** — `project/tests/view/test_view_boundary.gd` 에 "view/ui 의 .gd/.tscn/.tres 에 `res://tests/` 0건" 검사 + 검사 자체가 동작하는지 역검증(가짜 문자열을 넣은 배열에서 같은 grep 이 1건).
