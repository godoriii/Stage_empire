### C 인계 (sim-engineer, 같은 브랜치)

1. 위 실패 2건을 먼저 고친다: id 목록을 `["empty_room", "baseline_show", "baseline_plus_two_speakers"]` 로 갱신하거나, 원본 JSON `reference_layouts[].id` 에서 읽도록(권장 — 다음 레이아웃 추가 때 다시 안 깨짐). `test_build_data_qa.gd` 는 qa 파일이지만 `project/tests/sim/` 이라 sim-engineer 쓰기 범위 안; 손대면 PR 설명에 qa 확인 요청.
2. 새 레이아웃 키 이름: **`baseline_plus_two_speakers`**. BC21 테스트(`test_build_system.gd::test_bc21_two_more_speakers`, `test_coverage.gd::test_bc21_two_more_speakers_pure`)를 `_place_layout(bus, "baseline_plus_two_speakers")` + `_assert_expected(...)`(전 18키) / `_assert_layout("baseline_plus_two_speakers")` 로 교체하고 `BC21_*` 상수·`403|313|7766` 리터럴 삭제(AC2). `test_bc21` 의 "스피커가 음향을 올린다"(`assert_gt` 대 `baseline_show`) 단언은 두 레이아웃의 `expected.sound_bp` 비교로 유지 가능. `test_build_data_qa.gd::test_bc21_two_more_speakers_reach_dt6` 의 리터럴은 AC2 grep 대상 밖이지만 같은 방식으로 데이터 읽기로 바꾸면 좋다(qa 판단).
3. `blocked_cells` 정의: `Coverage.compute` 출력·`Coverage.KEYS` **맨 끝**(`upkeep_per_day` 뒤)에 `"blocked_cells"` 추가, 값 = 현재 `blocked` 딕셔너리의 셀을 G6(z → x 오름차순) 정렬한 `[[x, z], …]` 배열(int). 증분 아님, 빈 방이면 `[]`. `build.coverage_changed` 는 `cause` + KEYS 순서 그대로라 모든 cause 에 자동으로 실린다. AC3 테스트: `baseline_show`(21칸)·`baseline_plus_two_speakers`(23칸)에서 `blocked_cells` == 각 placements 의 `BuildConfig.cells_of` 합집합 G6 정렬, 철거 뒤 줄어듦, 스냅샷 복원 뒤 다음 `time.phase_changed {to:"evening"}` 의 `sync` 페이로드에 같은 목록. 기대값은 데이터 placements 로부터 계산(리터럴 불요). `reference_layouts[].expected` 에는 `blocked_cells` 가 없으므로 `_assert_expected` 의 키 순회와 충돌 없음.
4. `replay/test_replay_build.gd` 는 두 실행의 해시를 서로 비교할 뿐 리터럴 해시가 없고, `fixtures/build_oracle.json` 은 `coverage_changed` 페이로드를 저장하지 않으므로 키 추가로 갱신할 픽스처는 없다(확인함). `--check` 는 C 뒤에도 그대로 일치해야 한다.
