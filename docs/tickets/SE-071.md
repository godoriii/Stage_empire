## 목표

프로덕트 오너 요청(2026-10-20): "음악 테마는 직접 고를 수 있으면 좋겠다". 테마를 준비 단계의 결정으로 바꾸되, 늘 헤드라이너 장르를 고르는 게 정답이 되지 않도록 트렌드와 오프닝 장르로 긴장을 남긴다.

## 규칙 (추천안 채택)

- 제안 카드의 랜덤 `theme` → 랜덤 `trend`(요즘 뜨는 장르). RNG 호출 순서·횟수는 그대로.
- 준비 기둥 0에 **테마 장르** 선택(4장르 중 1, 필수).
- 헤드라이너 장르 = 테마: 수요 +20 %, 만족 +3 (기존 그대로).
- 테마 = 트렌드: 수요 +10 % (`balance.demand.trend_demand_pct`).
- 오프닝 장르 ≠ 테마: 오프닝 1팀당 만족 −2 (`balance.lines.opener_off_theme`), 오프닝 구간에 실현.

## 수용 기준

- [x] AC1. run.md·show.md·README 가 위 규칙으로 고쳐지고, 손 계산 예시 (a)(b) 숫자가 새 규칙에서도 성립(테마 = 기존 테마, 트렌드 불일치)하거나 갱신된다.
- [x] AC2. 엔진이 plan.theme 없으면 계획을 거부하고, 위 세 효과를 적용한다. 테스트 추가.
- [x] AC3. 봇: 무작위는 테마 균등, 합리적은 테마 = 헤드라이너 장르(트렌드 동점 우대). 1막 통과율이 목표(무작위 20~50 %, 합리적 70~90 %) 안.
- [x] AC4. 프로토타입 준비 화면에 테마 선택, 제안 카드에 트렌드 표시, 경고·리뷰 문구 반영.

## 결과

- 스펙(game-designer, 4969495): run.md·show.md·README, `balance.json` v2 (`trend_demand_pct` 10, `opener_off_theme` −2, `theme_match` 3 → 2). 손 계산 예시 (a) 73 B, (b) 55 C, 대조 74 A, 참고안 SH9·SH10.
- 엔진: 제안 `trend`, `plan.theme` 필수, 트렌드 ×110 %, `opener_theme` 줄, 미리보기 경고 예외. `node prototype/v2/test_engine.mjs` → 55 passed (SH1·SH2·SH6·SH8~SH10 갱신·추가).
- 봇: 무작위 테마 균등, 합리적 테마 = 헤드라이너 장르 + 오프닝 후보 3종 비교. 1막(1,000런, 시드 1 / 100001): 무작위 21.0 % / 23.7 %, 합리적 90.4 % / 91.1 %, 결정 하나 효과 81~82 %.
  - 합리적이 목표 상한(90 %)을 0.4~1.1 %p 넘고, 수요 −20 % 적자가 1.6 %(목표 5~20)로 낮다. `theme_demand_pct` 20 → 10 이면 적자 4.1~4.5 %, 합리적 89.6~91.8 % — 근본 개선이 아니고 예시 전부를 다시 계산해야 해서 이번엔 바꾸지 않는다. 프로덕트 오너 플레이 피드백과 함께 2막 수치 티켓에서 본다(결정 로그).
- 프로토타입: 준비 0단계 테마 선택(트렌드·시장 장르 수 표시, 기본값 = 트렌드), 테마 장르 아티스트 표시, 헤드라이너·오프닝 장르 불일치 경고, 제안 카드에 트렌드, 결과 리뷰 문구.
