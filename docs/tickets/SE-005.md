## 목표

sim-engineer 가 질문 없이 `project/sim/economy.gd`와 `project/tests/sim/test_economy.gd`를 쓸 수 있는 티어 1 경제 규칙 v0.
수익 2종(티켓, 바), 비용 4종(개런티, 임대, 유지비, 세금), 하루 1회 정산, 파산 조건과 구제 N회, 시작 자금이
전부 공식 + JSON 테이블로 정의되고, 손계산으로 재현되는 예시가 문서에 있으면 끝이다. 재미 판단과 구제 횟수 같은 선택은 사람에게 선택지로 올린다.

## 범위

- 포함:
  - `docs/gdd/economy.md` — 절 형식: 목적 → 규칙(입력/출력/공식) → 수치표(테이블 링크) → 수용 기준(테스트 케이스 목록) → 테스트 방법 → 열린 질문. 변경 이력 절.
  - 규칙에 반드시 들어갈 것:
    - 수익: 티켓(`가격 × 입장 수`), 바(`관객 × 구매율 × 객단가`, 원가율). 입장 수·관객 수는 v0 에서 **입력값**(관객 시스템은 `audience.md` 소관).
    - 비용: 아티스트 개런티(v0 는 등급별 고정표: 로컬/신인), 일일 임대료(티어별), 유지비(설치 가구 유지비 합 — 가구 테이블의 `upkeep_per_day` 필드 이름만 정의, 값은 furniture 티켓), 세금(일 순이익 양수분 × 세율; 세율 0 허용).
    - 즉시 반영 항목 vs 정산 반영 항목 구분(건설비·철거 환불 70%(PRD 결정)·개런티 선지급은 즉시, 나머지는 정산).
    - 정산 시점: `close` 구간 진입 틱 1회(틱 경계). 정산 결과 이벤트.
    - 파산: 정산 후 `cash < 0` → 구제 제안(긴급 대출: 금액·이자·상환 일수, 또는 스폰서 구제) → 남은 구제 횟수 0 이고 다시 음수면 게임 오버. PRD 의 "파산 = 게임 오버 + 구제 N회"는 바꾸지 않는다.
    - 시작 자금(티어 1).
    - 모든 금액은 정수. 반올림 규칙(내림/반올림, 어느 단계에서) 명시. 경제 v0 에는 난수 없음 — 있다면 어느 스트림(`economy`)을 어느 공식에서 쓰는지 명시.
  - `project/data/economy/economy.json` + `project/data/schemas/economy.schema.json`(신규). 티어별 행 또는 전역+티어 분리는 designer 선택. 후보 필드: `starting_cash`, `rent_per_day`, `tax_rate`, `bailout_count`, `bailout_loan_amount`, `bailout_interest_rate`, `bailout_repay_days`, `demolish_refund_rate`(0.7), `ticket_price_default/min/max`, `bar_purchase_rate`, `bar_avg_spend`, `bar_cost_rate`, `guarantee_by_grade`.
  - `project/data/tiers/tiers.json`·`tiers.schema.json`에 경제 필드를 붙이는 쪽을 택하면 `version` 2 로 올리고 economy.md 변경 이력에 기록.
  - `docs/gdd/events.md` — `economy.cash_changed` 확정("골격"→SE-005), 신규 `economy.day_settled`, `economy.bailout_offered`, `economy.bailout_taken`, `economy.bankrupt`(이름은 designer 가 확정) 행 추가.
  - `docs/gdd/README.md` — economy.md 상태 "v0".
- 제외(다른 티켓):
  - 구현(`project/sim/economy.gd`) — 후속 sim-engineer 티켓(SE-001 병합 후).
  - 티어 2+ 수익원(굿즈·스폰서·중계권), 스태프 인건비 상세(티어 2 `staff.md`), 아티스트 개런티 동적 공식(`artist.md`), 명성(`reputation.md`).
  - 관객 수 결정 공식(`audience.md`). v0 는 관객 수를 입력으로 받는다.
  - 봇 플레이 밸런스 검증(qa, 구현 후).
