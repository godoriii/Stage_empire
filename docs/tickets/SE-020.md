## 목표

헤드리스 GUT 는 더미 RenderingServer 라 `.gdshader` 컴파일을 검증하지 못한다(qa SE-004 "검증 불가"). 지금 셰이더 컴파일을 확인하는 유일한 경로는 qa 가 수동으로 돌리는 Xvfb(llvmpipe, gl_compatibility) 캡처다.
이 티켓은 그 수동 절차를 **스크립트 1개 + 비교기 1개** 로 만들고, CI 의 세 번째 job 이 PR 마다 돌리게 한다: 캡처 5장(SE-002 1 + SE-004 4)이 종료 코드 0 으로 생성되고 1920×1080 이며, 로그에 셰이더 컴파일 오류가 없고, 커밋된 기준 PNG 와의 픽셀 차를 출력한다.
픽셀 차 0 을 **실패 조건으로 쓸지**는 CI 러너의 llvmpipe 가 로컬과 같은 결과를 내는지 본 뒤 정한다(처음엔 보고만, 3회 연속 0 이면 `--strict` 로 전환 — producer 결정 로그).

## 경계 메모 (왜 메인 세션이 끼는가)

`.github/` 는 `tools/hooks/boundary_policy.json` 의 어느 에이전트 allow 에도 없다 → 에이전트는 쓸 수 없고 메인 세션(사람이 모는 세션, hook 제한 없음)이 커밋한다. 그래서 이 티켓의 워크플로 부분은 **스펙(YAML 전문)** 까지만 qa 가 쓰고, producer 가 병합 전에 메인 세션에서 같은 브랜치에 붙여 넣는다. `tools/` 아래 새 디렉터리도 qa 범위 밖(`tools/bot` 만)이라 스크립트는 `project/tests/view/screenshots/` 에 둔다(qa allow `project/tests`).

## 범위

- 포함(qa):
  - `project/tests/view/screenshots/recapture.sh <out_dir>`: SE-018 결과 절의 재캡처 명령 5개(SE-002 `grid_yaw45_zoom2.png` + SE-004 `a/b/c_yaw45_zoom2.png`·`b_yaw45_zoom0.png`)를 `xvfb-run -a -s "-screen 0 1920x1080x24" godot --path project --rendering-driver opengl3 --resolution 1920x1080 …` 로 `<out_dir>` 에 생성. 각 실행의 stdout/stderr 를 `<out_dir>/<name>.log` 에 저장하고 종료 코드 ≠ 0 이면 즉시 exit 1. 로그에 `SHADER ERROR`, `shader compilation`, `Failed to compile`, `error(` + `.gdshader` 패턴 중 하나라도 있으면 exit 1(메시지에 파일·패턴). 끝에 5장 전부 존재·1920×1080 을 `compare_png.gd --size-only` 로 확인. Godot 바이너리는 `GODOT_BIN` 또는 PATH(`tools/run_tests.sh` 와 같은 규칙).
  - `project/tests/view/screenshots/compare_png.gd`(`extends SceneTree`, `godot --headless --path project -s res://tests/view/screenshots/compare_png.gd -- <a.png> <b.png> [--strict] [--size-only]`): 두 PNG 를 `Image` 로 로드, 크기 불일치 → "size mismatch" + exit 2; 다른 픽셀 수·최대 채널 차(RGBA)를 한 줄(`diff_pixels=<n> max_channel_delta=<d>`)로 출력; `--strict` 면 `n > 0` 에서 exit 1, 아니면 exit 0. 비교 로직은 `PngCompare`(RefCounted, `static func diff(a: Image, b: Image) -> Dictionary`)로 분리해 GUT 가 단위 테스트한다. PIL·numpy 의존 없음(CI 에 파이썬 이미지 라이브러리를 깔지 않는다).
  - 단위 테스트 `project/tests/view/test_png_compare.gd`: 같은 이미지 → 0/0; 1픽셀 바꾼 사본 → 1 과 그 채널 차; 크기 다른 이미지 → 오류 코드; 커밋된 5장을 자기 자신과 비교 → 0(로드 경로 검증, LFS 체크아웃 전제).
  - 로컬 재현 리포트: qa 가 Xvfb 에서 `recapture.sh` 를 2회 돌려 5장 모두 커밋본과 픽셀 차 0, 2회 사이 픽셀 차 0 을 기록(결정성 증거).
  - 워크플로 스펙(YAML 전문, 티켓 결과 절): job `screenshots`(`needs: data`, ubuntu-latest, `apt-get install -y xvfb mesa-utils libgl1-mesa-dri`, `actions/checkout@v4` with `lfs: true`, `chickensoft-games/setup-godot@v2` 4.7.2, `godot --headless --path project --import`, `project/tests/view/screenshots/recapture.sh "$RUNNER_TEMP/shots"`, 5장 각각 `compare_png.gd` 비strict 실행(출력이 로그에 남음), 실패 시 `actions/upload-artifact@v4` 로 `$RUNNER_TEMP/shots` 업로드(`if: failure()`)). 기존 job 2개는 변경 0. 예상 소요 ≤ 3분(캡처 5 × 약 10초 + 설치).
- 포함(메인 세션): 위 YAML 을 `.github/workflows/ci.yml` 에 추가(같은 브랜치, 별도 커밋 `SE-020 ci: screenshots job`). 첫 PR 에서 job 이 녹색이고 5장의 `diff_pixels` 가 0 이면 결정 로그에 기록; 3회 연속 0 이면 `--strict` 전환(워크플로 1줄, 메인 세션).
- 제외(다른 티켓):
  - forward_plus(Vulkan) 컴파일 검증 — CI 러너에 Vulkan ICD 가 없다. 사람 PC 캡처(C3+C4 류)로 대체, 다음 사람 관문 때.
  - 스크린샷 기준 교체 자체 — SE-018(이 티켓은 그 기준을 그대로 쓴다).
  - `tools/run_tests.sh` 변경 — 없음(기본 테스트 실행 시간을 늘리지 않는다. 캡처는 CI 전용 job).
  - main 브랜치 보호 규칙에 `screenshots` job 을 필수 검사로 넣는 것 — 사람(리포지토리 설정, "되돌릴 수 없거나 외부로 나가는 행동"). status "사람이 할 일" 에 1줄로 올린다.

## 수용 기준

- [ ] AC3. `compare_png.gd`: 같은 파일 → `diff_pixels=0 max_channel_delta=0` exit 0; `--strict` 에서 1픽셀 다른 사본 → exit 1 과 `diff_pixels=1`; 크기 다른 파일 → exit 2; `--size-only` 는 크기만 검사. → `test_png_compare.gd` 4케이스(`PngCompare.diff` 단위) + qa 수동 실행 표

## 테스트 방법

- 헤드리스: `tools/run_tests.sh project/tests/view` → `test_png_compare.gd`.
- Xvfb(qa 로컬): `project/tests/view/screenshots/recapture.sh /tmp/claude-0/.../scratch/shots` → 5장; `for f in …; do godot --headless --path project -s res://tests/view/screenshots/compare_png.gd -- project/tests/view/screenshots/<dir>/$f <scratch>/shots/$f; done`.
