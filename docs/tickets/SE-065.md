## 배경 (SE-042, 정책 3 × 시드 30 × 30일)

- 무작위 정책도 파산 0/30(목표 30~90 %), 합산 파산율 0 %(목표 10~25 %), 구제 제안 0회, 최저 최종 자금 5,386.
- 실패 공연(disaster·poor) 0건 — M11(포기 대 실패) 판정 불가.
- 시드 분산이 거의 없음: frugal 명성 500 도달 22일 [22, 22], aggressive 15 [15, 15]; 등급도 정책마다 한 칸(frugal good 100 %, aggressive rave 99.5 %).
- 첫 선택 유발 사건(M8) frugal 7일·aggressive 5일(목표 ≤ 4).

## 목표

PRD 의 "멍청한 정책은 파산한다"와 "10분 안에 결정할 거리"를 봇 지표로 만족시킨다. 수치 조정이 우선이고, 새 규칙은 최소로(필요하면 결정 로그에 이유).

## 범위

- 포함(game-designer): 원인 진단(왜 무작위가 파산하지 않는가 — 비용 대비 수입 여유, 가격 반응 폭, 만족 → 등급 곡선, 입장 노이즈 폭 등을 지표·공식으로 추적해 1쪽 분석), 수치 조정안(데이터 JSON) + 해당 GDD 문서·기준 시나리오·`checks`·통합 기준 시나리오(reputation.md 30일 표) 갱신, 첫 결정 사건을 4일 안으로 당기는 방법(예: 신인 해금 임계, 첫 만석 조건, 승급 속도). 봇 목표 범위(bot_metrics.md)는 바꾸지 않는 것이 원칙 — 바꾸면 이유를 결정 로그로.
- 포함(qa): 조정 브랜치에서 봇 재측정(시드 30, 3정책 + v0_replay), 결과 표 비교(전/후), 데이터 리터럴로 고정된 테스트 갱신(데이터에서 읽게 바꾸는 것이 우선), 30일 리플레이 기준값 갱신 경로 확인.
- 제외: 새 시스템(스태프·위기 이벤트 — MVP 2차), UI 변경.

## 수용 기준

- [ ] AC1. 원인 분석 문서(`docs/gdd/balance_pass1.md` 또는 bot_metrics.md 부록)에 범위 밖 지표마다 원인 공식·수치.
- [ ] AC2. 조정 뒤 봇 재측정(시드 30): random 파산율 30~90 %, 합산 10~25 %(참고), frugal 파산 ≤ 5 %, aggressive ≤ 15 %, M4 random 실패+포기 ≥ 30 %, M8 frugal·aggressive ≤ 4, 시드 분산 — frugal·aggressive `rep500_day` Q1≠Q3 또는 등급 2칸 이상. 못 맞춘 항목은 이유와 다음 조정 후보.
