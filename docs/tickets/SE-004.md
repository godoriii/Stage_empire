## 목표

아트 디렉터(사람)가 최종 룩을 고를 수 있는 비교 자료를 만든다. 같은 플레이스홀더 오브젝트·같은 조명·같은 카메라에서
셀 단계 수·외곽선 두께·림라이트 유무만 다른 시안 3종을 키 하나로 바꿔 보고, 1080p 스크린샷과 프레임 비용 표를 받는다.
셰이더 상수는 전부 `.tres` 리소스에 있어 코드 수정 없이 아트 디렉터가 조정할 수 있어야 한다. 어느 시안을 고를지는 이 티켓이 정하지 않는다.

시안 정의(style-guide 의 후보 축을 조합. 사람이 바꿔도 된다):

| 시안 | 셀 단계 | 외곽선 | 림라이트 |
|---|---|---|---|
| A | 2 | 1px | 없음 |
| B | 3 | 2px | 있음 |
| C | 2 | 2px | 있음 |

## 범위

- 포함:
  - `project/view/shaders/toon.gdshader` — 셀 셰이딩. uniform: `cell_steps`(int), `shadow_tint`(color), `rim_enabled`(bool), `rim_strength`, `rim_color`, 머티리얼 슬롯 `base_color`, `accent_color`, `emissive_color`(style-guide 슬롯 이름 `base/accent/emissive`; `glass`는 제외).
  - `project/view/shaders/outline.gdshader` — 외곽선 패스(역면 헐 또는 스크린스페이스, 엔지니어 선택·"결과"에 근거 기록). uniform: `outline_px`(화면 픽셀 기준, 줌에 무관하게 일정), `outline_color`.
  - `project/view/shaders/params/toon_a.tres`, `toon_b.tres`, `toon_c.tres` — 위 표 값의 `ShaderMaterial`(또는 파라미터 Resource).
  - `project/view/scenes/shader_compare.tscn` + `shader_compare.gd` — 플레이스홀더 세트: 바 카운터(3×1, 높이 1.1), 무대(4×3, 높이 0.6), 캐릭터 캡슐(0.5×1.7) 5개, 벽 세그먼트, 바닥. 스테이지 조명 흉내 컬러 스포트 3개. 액션 `shader_variant_1/2/3`로 전환, 현재 시안 라벨.
  - `project/tests/view/screenshots/SE-004/{a,b,c}_yaw45_zoom2.png`, `b_yaw45_zoom4.png`(외곽선 두께 확인용) — 1920×1080.
  - `project/tests/view/perf/results/SE-004.md` — SE-003 씬 구성 B 에 시안 A/B/C 와 unlit 을 적용한 프레임 비용 표(SE-003 측정과 같은 절차. GPU 없는 환경이면 "측정 대기").
  - `project/tests/view/test_toon_shader.gd`, `test_shader_compare.gd`.
- 제외(다른 티켓):
  - 최종 시안 선택과 style-guide 갱신 — 사람(아트 디렉터). 선택 후 기본 머티리얼 적용은 후속 티켓.
  - `glass` 슬롯(투명), 포스트프로세스 색보정, 안개 볼륨·레이저 — 후속 조명 티켓.
  - 색약 팔레트 — UI/접근성 티켓.

## 수용 기준

- [ ] AC1. `toon.gdshader`와 `outline.gdshader`의 소스에 위에 적은 uniform 이름이 전부 선언되어 있고(텍스트 파싱), `load()`가 `null`이 아니다. → `test_toon_shader.gd::test_shader_files_declare_required_uniforms`
- [ ] AC2. `toon_a/b/c.tres`가 로드되고 파라미터가 표와 같다: A `(cell_steps=2, outline_px=1, rim_enabled=false)`, B `(3, 2, true)`, C `(2, 2, true)`. 세 파일이 같은 `toon.gdshader`를 가리킨다. → `test_toon_shader.gd::test_variant_params_match_table`
- [ ] AC3. `project/view/shaders/**/*.gd`와 `shader_compare.gd`에 셀 단계·외곽선 px·림 강도 리터럴이 없다(값은 `.tres`에서만). → `test_toon_shader.gd::test_no_shader_constants_in_code`
- [ ] AC4. `ShaderCompare.set_variant(i)` 호출 후 씬의 모든 `MeshInstance3D`(바닥 제외) `material_override`가 시안 i 의 머티리얼이고 외곽선 패스가 붙어 있다. 1→2→3→1 전환 후 상태가 처음과 같다. → `test_shader_compare.gd::test_set_variant_applies_to_all_meshes`
- [ ] AC5. `shader_variant_1/2/3` 액션이 `InputMap`에 등록된다(SE-002 의 `InputActions` 확장). → `test_shader_compare.gd::test_variant_actions_registered`
- [ ] AC6. 스크린샷 4장이 존재하고 1920×1080 이다. 세 시안 스크린샷의 카메라(요 45°, 줌 2)가 동일하다 — 씬에 카메라 상태 고정 플래그가 있고 스크린샷은 그 상태로 찍는다. → `test_shader_compare.gd::test_screenshots_exist_1080p`
- [ ] AC7. 외곽선 두께가 화면 픽셀 기준으로 일정하다: `b_yaw45_zoom2.png`와 `b_yaw45_zoom4.png`에서 캐릭터 캡슐 외곽선이 둘 다 약 2px(1~3px). → qa 수동 확인(이미지 확대), 리포트에 두 이미지의 측정 위치·픽셀 폭 기록
- [ ] AC8. 비용 표 `project/tests/view/perf/results/SE-004.md`에 unlit / A / B / C 4행(평균 fps, 1% low, 평균 ms)이 있다. GPU 없는 환경이면 "측정 대기(사람 실행 필요)"로 비워 두되 측정 명령은 적는다. 통과 기준은 두지 않는다(사람의 선택 자료). → qa 리포트에서 대조
- [ ] AC9. `tools/run_tests.sh project/tests/view` 전체 녹색. → qa 리포트 실행 로그
