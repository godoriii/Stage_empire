## 목표

아트 디렉터(사람)가 최종 룩을 고를 수 있는 비교 자료를 만든다. 같은 오브젝트·같은 조명·같은 카메라에서
셀 단계 수·외곽선 두께·림라이트 유무만 다른 시안 3종을 인자 하나(`--material=a|b|c`)와 키 하나(1/2/3)로 바꿔 보고,
1080p 스크린샷과 프레임 비용 표를 받는다. 셰이더 상수는 전부 `.tres` 리소스에 있어 코드 수정 없이 조정할 수 있어야 한다.

시안은 **두 무대**에 같은 머티리얼 리소스로 적용된다:

- **성능**: SE-013 스파이크(`spike_crowd.tscn`, 구성 E = 관문 구성·군중 그림자 off)의 군중 MultiMesh + 무대 프록시 박스. 측정은 `measure_spike.tscn -- --config=E --material=<id>`.
- **캡처**: SE-002 그리드 샌드박스(`grid_sandbox.tscn`)에 `--material=<id>` 를 주면 플레이스홀더 세트(바·무대·캐릭터·벽)가 생성되고 시안이 적용된다. 스크린샷은 기존 `--se-screenshot=` 로 찍는다.

어느 시안을 고를지는 이 티켓이 정하지 않는다(사람 결정 1건, 아래 "사람 결정"). 사람이 할 일은 SE-013 실측과 합쳐 **한 번**이다(아래 "테스트 방법 — 사람 PC").

시안 정의(style-guide 의 후보 축 조합. 사람이 바꿔도 된다):

| 시안 | 셀 단계 | 외곽선 | 림라이트 |
|---|---|---|---|
| default | — (스파이크·샌드박스의 기존 `StandardMaterial3D`, 비교 기준) | 없음 | 없음 |
| A | 2 | 1px | 없음 |
| B | 3 | 2px | 있음 |
| C | 2 | 2px | 있음 |

## 범위

- 포함:
  - `project/view/shaders/toon.gdshader` — 셀 셰이딩. uniform: `cell_steps`(int), `shadow_tint`(color), `rim_enabled`(bool), `rim_strength`(float), `rim_color`(color), 머티리얼 슬롯 `base_color`, `accent_color`, `emissive_color`(style-guide 슬롯 이름 `base/accent/emissive`; `glass` 는 제외). 정점색 `COLOR` 를 `base_color` 에 곱한다(스파이크 군중은 `vertex_color_use_as_albedo` 로 인스턴스마다 색이 다르다 — 시안을 씌워도 군중 색 분포가 유지돼야 default 와 비교가 된다).
  - `project/view/shaders/outline.gdshader` — 외곽선 패스. **역면 헐(inverted hull)을 `ShaderMaterial.next_pass` 로** 붙인다(MultiMesh 군중에 노드 추가 없이 적용되는 유일한 방식. 스크린스페이스는 후속 포스트프로세스 티켓). uniform: `outline_px`(화면 픽셀 기준, 직교 카메라 줌 `size` 에 무관하게 일정 — `VIEWPORT_SIZE`·`PROJECTION_MATRIX` 로 환산), `outline_color`.
  - `project/view/shaders/params/toon_a.tres`, `toon_b.tres`, `toon_c.tres` — 위 표 값의 `ShaderMaterial`(shader = `toon.gdshader`, `next_pass` = 같은 시안의 외곽선 `ShaderMaterial`). 외곽선 머티리얼은 `outline_a.tres`, `outline_b.tres`, `outline_c.tres`(A 는 `outline_px = 1`).
  - `project/view/shaders/shader_variants.gd` — `ShaderVariants`(RefCounted, static). 시안 id 목록 `["default", "a", "b", "c"]`, `resolve_material_id(exported: String, user_args: PackedStringArray, default_id: String) -> String`(`--material=` 해석, 소문자화, SE-013 `SpikeCrowd.resolve_config_id` 와 같은 우선순위), `load_material(id) -> ShaderMaterial`(`default` 와 없는 id 는 `null`; 호출자가 구분), `is_valid_id(id) -> bool`, `apply(root: Node, id: String, exclude: Array[Node]) -> int`(루트 아래 모든 `GeometryInstance3D`(`MeshInstance3D`·`MultiMeshInstance3D`)의 `material_override` 를 시안 머티리얼로, `default` 면 `null` 로 되돌림. 적용한 수를 반환). `--material=` 해석은 이 파일 한 곳에만 둔다.
  - `project/view/scenes/shader_placeholders.gd` + `shader_placeholders.tscn` — `ShaderPlaceholders`(Node3D). 플레이스홀더 세트: 바 카운터(3×1, 높이 1.1), 무대(4×3, 높이 0.6), 캐릭터 캡슐(0.5×1.7) 5개, 벽 세그먼트 1개, 스테이지 조명 흉내 컬러 스포트 3개(림라이트 확인용). 치수·색·라이트 값은 `project/view/scenes/shader_placeholders.tres`(`ShaderPlaceholderSet` Resource)에서 읽는다. 바닥은 SE-002 `GridView` 그대로(시안 적용 제외).
  - `project/view/scenes/grid_sandbox.gd` 확장 — 인자 `--material=<id>` 가 있으면 `ShaderPlaceholders` 를 자식으로 생성하고 `ShaderVariants.apply()` 로 시안 적용(바닥·커서·HUD 제외). 없는 id 면 `push_error` + 종료 코드 2. 인자 `--se-zoom=<0..3>` 추가(줌 인덱스 지정, 외곽선 두께 확인용). 액션 `shader_variant_1/2/3` 으로 런타임 전환, `DebugHud` 에 현재 시안 한 줄("시안: a"). **`--material=` 이 없으면 SE-002 와 동작·화면이 같다**(플레이스홀더 미생성, 기존 스크린샷·테스트 불변).
  - `project/view/input/input_actions.gd` — `shader_variant_1/2/3`(키 1/2/3) 등록(SE-002 `InputActions` 확장, `KEY_` 리터럴은 이 파일에만).

### 외곽선 `next_pass` 구현 메모

- 뷰 공간 정점을 뷰 공간 법선 방향으로 `outline_px × (m/px)` 만큼 밀고, `cull_front` 로 뒷면만 `outline_color` 단색(unshaded)으로 그린다(`skip_vertex_transform`).
- 환산식(직교): `PROJECTION_MATRIX[1][1] = 2 / size`(size = 세로 가시 범위 m)이므로 **1 px = size / VIEWPORT_SIZE.y = 2 / (|PROJECTION_MATRIX[1][1]| · VIEWPORT_SIZE.y) m** 이다. 줌(size)이 바뀌면 월드 두께가 같은 비율로 바뀌어 화면 두께는 일정하다. 원근이면(`PROJECTION_MATRIX[3][3] < 0.5`) 뷰 깊이 −z 를 곱한다(이 게임은 쓰지 않음).
- **`abs()` 가 필요하다**: Compatibility(OpenGL) 렌더러에서는 `[1][1]` 이 음수로 들어온다(렌더 타깃 Y 뒤집기). 처음 구현은 부호 그대로 써서 헐이 안쪽으로 들어가 외곽선이 보이지 않았다. Xvfb 캡처로 발견해 고쳤다.
- 한계: BoxMesh 는 면마다 법선이 갈라져 있어 모서리에 1~2px 틈이 생길 수 있다(스크린스페이스 외곽선은 후속 티켓). 무대 프록시(`cast_shadow` ON)에서는 외곽선 패스도 셰도우 패스에 들어간다. 셰도우 맵에서는 헐이 라이트 투영 기준으로 조금 부풀지만 군중(E, cast_shadow OFF)은 해당 없다.

### 티켓 문구와 다르게 해석한 것 (리뷰어 확인 요청)

1. **AC8 "TileCursor 메시 `material_override == null`"**: TileCursor 의 `Highlight` 메시는 SE-002 부터 자체 `material_override`(StandardMaterial3D)를 갖는다. 그래서 테스트는 "바닥·커서 메시의 override 가 적용 전 값 그대로이고 ShaderMaterial 이 아니다"와 "GridView 메시는 null"을 검사한다. 커서는 `exclude` 로 빠지므로 동작은 티켓 의도와 같다.
2. **기본 출력 파일명**: 시안이 `default` 면 SE-013 과 같은 `SE-013_<config>.json` 을 쓰고, 그 밖의 시안이면 `SE-013_<config>_<material>.json` 을 쓴다(AC7 `SE-013_E_c.json` 충족). "`--material` 없이 실행하면 SE-013 과 출력 동일" 조건과 맞추려고 이렇게 했다. 사람 PC 명령은 전부 `--out=` 을 주므로 영향이 없다. JSON 에는 `material: "default"` 키가 하나 늘어난다(티켓이 요구한 키 추가).
3. **`apply()` 대상**: 티켓 괄호대로 `MeshInstance3D`·`MultiMeshInstance3D` 만 바꾼다. Label3D·Sprite3D·파티클은 툰 셰이더를 씌우면 글자·빌보드가 깨지므로 대상이 아니다(테스트로 고정).
4. **입력 액션**: `InputActions.ALL`·`register()` 는 SE-002 의미(카메라 9개) 그대로 두었다. 시안 액션은 `SHADER_VARIANT_ACTIONS` + `register_shader_variants()` 로 따로 등록한다. 기존 `test_actions_registered`(ALL == 9개)와 qa 테스트를 고치지 않으려고 이렇게 했다. 샌드박스는 둘 다 등록하고, 시안 키는 플레이스홀더가 있을 때(`--material=`)만 반응한다.
5. **accent 슬롯**: 메시 하나에 머티리얼 하나라서, 정점 알파 0 인 영역을 accent 로 본다(albedo × accent_color). 플레이스홀더는 바 카운터 윗면을 accent(장르 pop 강조색 정점색)로 칠했다. 시안 .tres 의 base/accent_color 는 흰색이라 default 와 같은 색이 나온다. 아트 디렉터는 이 값을 바꿔 슬롯 색을 틴트할 수 있다. 군중은 정점 알파가 1 이라 영향이 없다.
6. **림**: 역광 가중 `(1 − L·V)/2` 를 곱한다. 이것이 없으면 정면 백색광(샌드박스 Sun)이 실루엣 전체를 하얗게 칠해 무대 조명 색이 묻어나지 않았다. 상수가 아닌 기하 항이라 uniform 으로 빼지 않았다. `rim_width` 는 uniform 으로 추가했다(.tres 0.35).
7. `project/ui/hud/debug_hud.gd` 는 "포함" 목록에 파일명이 없다. "DebugHud 에 현재 시안 한 줄" 요구를 구현하려고 고쳤다(ui/ 는 쓰기 범위 안).
