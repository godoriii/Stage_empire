## 목표

`project/core/`에 게임 시간의 단일 출처가 생긴다. 고정 10 tick/초로만 시간이 가고, 하루가 낮→저녁→공연→마감 4구간을 돌며,
배속 0~3이 구간별 허용 범위 안에서만 바뀌고, 모든 난수가 시드 고정 RNG 한 곳에서 나오며, 시스템끼리는 이벤트 버스로만 말한다.
"같은 시드 + 같은 명령 열 = 같은 상태"가 헤드리스 리플레이 테스트로 증명되면 끝이다. 화면은 없다.

## 범위

- 포함:
  - `project/core/sim_config.gd` — `res://data/sim/sim.json` 로더(`SimConfig`, RefCounted). 틱 수·구간·배속 허용표를 여기서만 읽는다.
  - `project/core/event_bus.gd` — `EventBus`(RefCounted). `subscribe / unsubscribe / publish`, 디스패치 중 발행은 FIFO 큐잉.
  - `project/core/rng.gd` — `SeededRng`(RefCounted). 마스터 시드 + 이름 있는 스트림, 상태 get/set.
  - `project/core/tick.gd` — `TickLoop`(RefCounted). `advance(n)`, `step(delta_s)`, 구간 전환, 배속, 명령 이벤트 큐, `snapshot()/restore()`.
  - `project/tests/sim/test_sim_config.gd`, `test_event_bus.gd`, `test_rng.gd`, `test_tick.gd`, `test_core_boundary.gd`, `replay/test_replay_tick.gd`.
- 제외(다른 티켓):
  - 실시간 드라이버(`_physics_process`에서 `TickLoop.step()`을 부르는 Node) — `view/` 소관, 후속 render-engineer 티켓.
  - 세이브 파일 직렬화(JSON→gzip)·스키마 마이그레이션·오토세이브 파일 쓰기 — 후속 sim-engineer 티켓. 여기서는 `snapshot()` Dictionary 까지만.
  - 경제·관객·아티스트 등 실제 시스템 — SE-005 이후 구현 티켓.
  - 배속 UI, 구간 표시 HUD — render-engineer.
  - `docs/gdd/events.md` 갱신 — SE-006(game-designer). 이 티켓은 거기 정의된 이름만 쓴다. 이름이 더 필요하면 "결과" 절에 적고 멈춘다.

## 수용 기준

측정 가능한 문장만. 각 항목은 테스트 하나와 짝이 된다. 이벤트 이름·페이로드·클램프 규칙은 `docs/gdd/tick.md`가 우선이며, 아래 이름은 SE-006 이 바꾸면 그대로 따른다.

- [ ] AC1. `SimConfig.load()`가 `res://data/sim/sim.json`을 읽어 `ticks_per_second == 10`, 구간 4개가 `day, evening, show, close` 순서로 `ticks/pausable/speeds`를 가진다. `project/core/**/*.gd` 어디에도 `10`, `1800`, `600`, `900` 같은 구간·틱 리터럴이 없다. → `test_sim_config.gd::test_loads_sim_json`, `test_core_boundary.gd::test_no_tick_literals_in_core`
- [ ] AC2. `TickLoop.new(config, seed).advance(1)` 후 `tick == 1`. `advance(3300)` 동안 `tick.advanced`가 정확히 3,300회, 페이로드 `{tick, phase}`의 `tick`이 1..3300 단조 증가로 발행된다. → `test_tick.gd::test_advance_increments_tick`, `test_tick.gd::test_tick_advanced_published_once_per_tick`
- [ ] AC3. 하루 안의 틱(`tick_in_day`)이 sim.json 구간 길이의 누적 경계에서 `day → evening → show → close` 로 바뀌고, 각 전환마다 `time.phase_changed {from, to, day, tick}`가 전환 순서대로 1회씩 발행된다. 테스트는 경계를 sim.json 에서 계산하되 하루 총 길이가 3,300틱임을 함께 단언한다. → `test_tick.gd::test_phase_boundaries_from_config`, `test_tick.gd::test_phase_changed_events_in_order`
- [ ] AC4. `close` 구간(`ticks == 0`)에서는 `advance()`/`step()`이 틱을 진행시키지 않고(`tick` 불변), `time.next_day_requested`를 받으면 `day + 1`, `phase == "day"`, `tick_in_day == 0`이 된다. → `test_tick.gd::test_close_holds_until_next_day_requested`
- [ ] AC5. `time.speed_requested {speed}`가 현재 구간의 `speeds`에 있으면 적용되고 `time.speed_changed`가 발행된다. 없으면 배속 불변, `time.speed_rejected`(tick.md 의 이름) 발행. 구간 진입 시 현재 배속이 허용 밖이면 tick.md 의 클램프 규칙대로 바뀐다(예: show 진입 시 3→1, close 진입 시 →0). → `test_tick.gd::test_speed_allowed_per_phase`, `test_tick.gd::test_speed_rejected_keeps_state`, `test_tick.gd::test_speed_clamped_on_phase_enter`
- [ ] AC6. `step(delta_s)`는 누적기 기반이다: 배속 1에서 `step(0.1)` 100회 → 정확히 100틱, 배속 3에서 → 300틱, 배속 0에서 → 0틱. `step(0.05)` 2회와 `step(0.1)` 1회의 결과가 같다. → `test_tick.gd::test_step_accumulator_by_speed`
- [ ] AC7. 명령 이벤트(`time.*_requested`)는 받은 즉시가 아니라 다음 틱 경계에서 처리된다: 틱 처리 중(핸들러 안)에 보낸 `time.speed_requested`는 그 틱의 `tick.advanced` 이후에 적용된다. 한 틱의 순서는 tick.md 대로 "명령 처리 → 시스템 업데이트 → `tick.advanced`". → `test_tick.gd::test_commands_applied_at_tick_boundary`
- [ ] AC8. `EventBus`: 같은 이벤트의 구독자는 구독 순서대로 호출된다. 핸들러 안에서 `publish()`하면 현재 디스패치가 끝난 뒤 FIFO 로 전달된다(재진입 없음). `unsubscribe` 후에는 호출되지 않는다. 페이로드 값에 `Object`가 있으면 `push_error` 후 `false`를 반환하고 전달하지 않는다. → `test_event_bus.gd::test_delivery_in_subscription_order`, `::test_nested_publish_is_queued_fifo`, `::test_unsubscribe_stops_delivery`, `::test_rejects_object_payload`
- [ ] AC9. `SeededRng`: 같은 시드의 두 인스턴스에서 `stream("audience").randi()` 10,000회가 전부 같다. 다른 시드면 첫 100개 중 하나 이상 다르다. `stream("audience")`를 1,000번 뽑아도 `stream("events")`의 다음 값은 바뀌지 않는다(스트림 독립). `get_state()`→`set_state()` 왕복 후 이어지는 100개가 원본과 같다. 스트림 이름 목록은 tick.md 의 v0 목록을 쓴다. → `test_rng.gd::test_same_seed_same_sequence`, `::test_different_seed_differs`, `::test_streams_independent`, `::test_state_roundtrip`
- [ ] AC10. `snapshot()`은 tick.md 가 정한 필드(`schema_version, seed, tick, day, phase, tick_in_phase, speed, rng`)를 기본형만으로 담은 Dictionary 를 돌려준다. `restore(snapshot)` 뒤 `advance(N)`한 상태의 `JSON.stringify(snapshot())`이, 복원 없이 연속으로 `advance(N)`한 것과 같다. `tick.advanced` 핸들러 안에서 부른 `snapshot()`은 빈 Dictionary 를 돌려주고 `push_error`한다(틱 경계에서만 세이브). → `test_tick.gd::test_snapshot_restore_equivalence`, `test_tick.gd::test_snapshot_rejected_mid_tick`
- [ ] AC11. 리플레이: 시드 42, 같은 명령 스크립트(지정 틱에서의 배속 변경, close 마다 `next_day_requested`)로 두 `TickLoop`을 2일 + 500틱 돌리면 최종 `snapshot()` JSON 과 발행된 이벤트 열(이름+페이로드)이 완전히 같다. → `replay/test_replay_tick.gd::test_two_runs_identical`
- [ ] AC12. `project/core/**/*.gd` 에 `extends Node`, `_process(`, `_physics_process(`, `get_node(`, `Time.` 가 없고, `randi(`/`randf(`/`randomize(`/`RandomNumberGenerator`는 `rng.gd` 밖에 없다. 모든 클래스가 `class_name` + `RefCounted` 또는 `Resource`. → `test_core_boundary.gd::test_core_has_no_node_or_direct_random`
- [ ] AC13. `tools/run_tests.sh project/tests/sim` 전체 녹색, `python3 tools/validate_data.py` 통과, `project/core/*.gd` 각각에 `project/tests/sim/test_<이름>.gd` 짝이 있어 `tools/hooks/check_commit.py`가 커밋을 막지 않는다. → qa 리포트의 실행 로그
- [ ] AC14. 발행·구독하는 모든 이벤트 이름이 `docs/gdd/events.md` 표에 있다(표에 없는 이름 0개). → reviewer 검사(`docs/reviews/SE-001.md`)

## 경계 확인

- 쓰는 폴더: `project/core/`, `project/tests/sim/`(하위 `replay/` 포함)
- 읽기만 하는 폴더: `project/data/sim/sim.json`, `docs/gdd/tick.md`, `docs/gdd/events.md`, `CLAUDE.md`
- 필요한 이벤트(발행/구독) — `docs/gdd/events.md` 기준, 최종 이름은 SE-006 이 확정:
  - 발행(상태): `tick.advanced {tick, phase}` (골격 확정), `time.phase_changed {from, to, day, tick}`, `time.speed_changed {speed}`, `time.speed_rejected {speed, reason}` (뒤 3개는 SE-006 신규)
  - 구독(명령): `time.speed_requested {speed}` (골격 확정), `time.next_day_requested {}` (SE-006 신규)
- 필요한 데이터 테이블/필드: `sim.json`의 `ticks_per_second`, `phases[].id/ticks/pausable/speeds` (기존). RNG 스트림 목록·스냅샷 `schema_version` 등 새 필드가 필요하면 SE-006 에서 game-designer 가 넣는다. sim-engineer 는 `project/data/`를 고치지 않는다.
- 금지: `Node` 상속, `_process`, 직접 난수, `view/`·`ui/` 참조, 코드 안의 구간·틱 리터럴.
