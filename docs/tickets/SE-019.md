## 목표

가구·설비·캐릭터 모델이 네 슬롯(`base`/`accent`/`emissive`/`glass`)을 **어떻게 표기하는지**를 한 문단으로 확정한다. 지금 `toon.gdshader:40-42` 는 "정점 알파가 0 인 곳 = accent" 라는 암묵 규약을 쓰는데(SE-004 프로토타입, `accent_color` 가 흰색이라 시각 영향 0), 이는
(1) glTF 임포트에서 정점 알파가 의미 채널이 되고 (2) `glass`(투명) 슬롯과 충돌하며 (3) 군중 MultiMesh 인스턴스 색의 알파가 1 미만이면 accent 로 오인된다(qa 5, reviewer 후속 A).
확정 결과가 코드와 다르면 코드 변경은 **후속 render 티켓**으로 돌리고 이 티켓은 문서만 낸다. **룩에는 영향이 없다**(어느 안이든 화면의 색 결과는 같다 — 슬롯을 "어디에 저장하나" 의 문제). 그래서 사람 결정이 아니라 producer 가 추천안을 채택하고 결정 로그에 남긴다.

## 범위

- 포함(1차, game-designer — `docs/gdd/materials.md` 신규, `docs/gdd/README.md` 표 행 1개):
  - 슬롯 4종 정의(용도, 기본 색 출처, 상태 변형(켜짐/고장/철거중)과의 관계 — style-guide "상태 변형" 행과 모순 없이).
  - 표기 방식 3안 비교표: (a) 정점 알파 0 = accent(현행) / (b) **슬롯 = 별도 서피스**(glTF 머티리얼 이름 = 슬롯 이름, 메시 서피스 하나당 슬롯 하나) / (c) UV2.x 로 슬롯 id 인코딩(단일 서피스). 비교 열: glTF·Blender 표준 워크플로 호환, 생성 에셋 린터로 검사 가능한가, 드로우콜(서피스 수), 군중 MultiMesh 인스턴스 색(`COLOR`)과의 충돌, `glass` 투명 패스 분리 가능성, 외곽선 패스(`next_pass`)와의 관계, 툰 셰이더 변경 필요 여부.
  - **채택안 1개 + 근거.** producer 추천 초안: **(b) 별도 서피스** — glTF 머티리얼 = 슬롯이라 Blender·생성 파이프라인 모두 자연스럽고, 린터가 "서피스 이름이 4종 중 하나" 만 검사하면 되며, `glass` 가 저절로 분리(투명 머티리얼·외곽선 제외)되고, 정점 알파를 의미 채널로 쓰지 않아 군중 인스턴스 색·투명과 충돌이 0 이다. 비용은 서피스 수만큼의 드로우콜(가구 소형 2~3)이고 티어 1 수백 오브젝트에서 무시할 수준. game-designer 가 반박 근거(수치)가 없으면 (b) 로 확정하고, 다른 안을 추천하면 결과 절에 비교표와 함께 적는다 → producer 가 채택안을 결정 로그에 기록(사람에게 묻지 않음).
  - 채택안에 따른 부속 규약: 정점 알파는 의미 없음·1.0 고정((b)/(c) 인 경우), 군중 MultiMesh 는 `COLOR.rgb` 만 base 에 곱하고 알파 1, 슬롯별 색은 서피스 머티리얼 파라미터(`base_color`/`accent_color`/`emissive_color`)에서, 오브젝트별 색 변형은 머티리얼 복제가 아니라 인스턴스 파라미터로 한다는 원칙(구현 방식은 render 티켓 몫, 여기서는 "복제 금지" 만).
  - `glass` 슬롯: 투명(알파 블렌드), 외곽선 `next_pass` 제외, 그림자 캐스팅 off — 한 문단. 셰이더 파일은 후속(이 티켓은 규약만).
  - "룩 영향 없음" 을 명시한 한 줄(채택안이 화면 색 결과를 바꾸지 않는 이유).
- 포함(2차, art-pipeline — `tools/assets/GLTF_SPEC.md` 신규): glTF 2.0 임포트 규약 — 서피스/머티리얼 이름 규칙(정확히 `base|accent|emissive|glass`, 그 밖의 이름은 거부), 서피스 없는 슬롯 허용(base 는 필수), 정점 알파 1.0, 단위 m·+Y 업·-Z 전방·피벗 바닥 중심(style-guide "포맷" 행과 동일), 폴리곤 예산 행 참조, 린터가 검사할 항목 체크리스트(구현은 후속 art-pipeline 티켓, 이 티켓은 스펙만). 생성 프롬프트 템플릿(style-guide 하단)에 슬롯 서피스 요구를 한 줄 덧붙일 문구 제안.
- 포함(결과 절): `toon.gdshader` 현 구현과 채택안의 일치 여부. 불일치(예: (b) 채택 시 `:40-42` accent 알파 분기가 죽은 코드)면 후속 render 티켓 요청 문구(바꿀 줄, `.tres` 영향, 테스트 영향)를 적는다. 코드는 바꾸지 않는다.
- 포함(메인 세션): `docs/style-guide.md` "머티리얼 슬롯 이름" 행을 "초안" → "확정" 으로, 채택안 한 구절 + `docs/gdd/materials.md` 링크(문구는 결과 절에 game-designer 가 적는다).
- 제외(다른 티켓):
  - `toon.gdshader` 변경, `glass` 셰이더, 인스턴스 파라미터 구현 — 후속 render-engineer 티켓(이 티켓 결과 뒤 producer 발행).
  - glTF 린터 구현(`tools/assets/lint_gltf.py`) — 후속 art-pipeline 티켓.
  - 팔레트·폴리곤 예산 확정 — 별도.

3. 거부 규칙: 그 밖의 이름(대소문자 변형, `base.001` 같은 DCC 접미, 재질 이름), 머티리얼 없는 primitive, `base` 서피스 없음, 같은 슬롯 서피스 2개 이상 → 거부(메시지에 파일·머티리얼 이름).
4. 서피스 없는 슬롯 허용: `accent`/`emissive`/`glass` 는 선택, `base` 는 필수. 서피스 수 1~4.
5. 정점 색: 넣지 않는 것이 기본. `COLOR_0` 가 있으면 알파는 전부 1.0(아니면 거부), RGB 가 흰색이 아니면 경고(M2: base 에만 곱해짐).
6. 텍스처 없음: `images`/`textures` 0, 머티리얼은 baseColorFactor 만(미리보기용, 런타임은 슬롯 파라미터 — materials.md Q1). 사실적 텍스처 금지(style-guide).
7. 메시 노드 1개(v0, style-guide 프롬프트 "single mesh"), 스킨·애니메이션은 캐릭터 티켓에서 별도.
8. 폴리곤 예산: style-guide "폴리곤 예산" 행 참조(가구 소형 ≤ 300, 대형 설비 ≤ 1,500, 캐릭터 ≤ 800, LOD1 ≤ 150 tri) — 서피스 합계 기준.
9. 캐릭터(인스턴싱 대상)는 `glass` 금지.
10. Godot 4.7.2 임포트 뒤 슬롯 이름이 남는 위치(서피스 이름 / 서피스 머티리얼 `resource_name`)와 Blender 접미 처리 확인 방법(materials.md Q5).
11. 린터 체크리스트(구현은 후속 art-pipeline 티켓 `tools/assets/lint_gltf.py`): 위 2~9 를 항목별로 — 이름 ∈ 4종 / `base` 존재 / 슬롯 중복 없음 / 머티리얼 없는 primitive 없음 / 정점 알파 = 1.0 / 텍스처 0 / 메시 노드 1 / tri 예산 / 피벗(AABB 최소 y = 0, x·z 중심 ≈ 0) / 캐릭터 glass 없음.
12. 생성 프롬프트 템플릿 덧붙일 문구 제안(style-guide 하단, 메인 세션 적용): 둘째 줄의 `single mesh` 를 `single mesh with material slots named exactly base, accent (optional), emissive (optional), glass (optional), no vertex colors` 로.

**남은 질문**(materials.md "열린 질문"): Q1 슬롯 색을 가구 테이블에 둘지(추천: `project/data/furniture/*.json` 에 슬롯별 팔레트 id, 후속 스키마 티켓), Q2 캐릭터 `accent` 허용(추천: 허용), Q3 상태 변형 실제 값(팔레트 티켓), Q4 드로우콜 측정(티어 1 대표 장면), Q5 Godot 임포트 뒤 슬롯 이름 위치(art-pipeline 2차·R-B), Q6 SE-021 `ss` 채택 시 glass 외곽선 제외(깊이 미기록으로 자동 — 확인만).
