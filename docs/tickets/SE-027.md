## 목표

`.glb` + `META.json` 한 쌍을 받아 GLTF_SPEC §10 의 L1~L10 을 판정하는 헤드리스 린터(표준 라이브러리만, Godot 불필요)를 만든다. 거부(exit 1)/경고(exit 0) 결과를 `project/assets/review-queue/<asset-id>/lint.json` 에 항목 id 별로 남긴다. 이 린터가 있어야 SE-041 의 첫 슬롯 서피스 에셋이 검수 큐에 들어갈 수 있다(PRD "자동 검사(폴리곤 수, 피벗 위치, 스케일, 머티리얼 슬롯)").

## 범위

- 포함:
  - `tools/assets/lint_gltf.py <asset.glb> <META.json> [--out <lint.json>] [--config tools/assets/lint_config.json]` — L1~L10 전부 + 덧붙임 3건(`NORMAL` 존재: 거부, 미사용 머티리얼: 경고, `extensionsRequired` 비어 있음: 거부). 메시지 형식은 §3 표(파일명·머티리얼 이름·primitive 번호). 종료 코드: 0 통과(경고 포함) / 1 거부 / 2 인자·파일 오류.
  - `tools/assets/lint_config.json` — 허용 오차(피벗 0.01 m, 높이 ±5 %, 정점 알파 1e-4)와 카테고리별 삼각형 예산(style-guide 행 값: 소형 300 / 대형 1,500 / 캐릭터 800 / LOD1 150). **코드에 수치 리터럴 0**. GLTF_SPEC §7 의 수치 복사 문구를 "(복사본, 기준은 style-guide 행; 린터는 `lint_config.json` 을 읽는다)" 로 정리(reviewer SE-019 발견 낮음 2).
  - `META.json` 형식 정의(§10 입력): `{asset_id, category: "furniture_small"|"furniture_large"|"character"|"lod1", footprint: [w, d], height_m, ticket}` — GLTF_SPEC 에 절 추가. SE-028 가구 테이블의 `footprint`·`height_m` 와 같은 이름을 쓴다(game-designer 가 SE-028 에서 확정; 다르면 SE-028 이 이긴다).
  - 픽스처 `tools/assets/fixtures/` — `q5_probe/make_probe_glb.py` 를 확장해 생성: `slots4.glb`(통과), `bad_names.glb`(L1·L4), `dup_two_materials.glb`·`dup_shared_material.glb`(L3), `vertex_alpha.glb`(L5), 추가로 피벗 오프셋(L9), 예산 초과(L8), 텍스처 포함(L6), 노드 2개(L7), 캐릭터 glass(L10), `NORMAL` 없음, 미사용 머티리얼(경고), `extensionsRequired` 비어 있지 않음. 생성 스크립트와 생성물 둘 다 커밋(생성물은 작으므로 LFS 불필요 — 각 10 KB 미만 확인).
  - `tools/assets/test_lint_gltf.py`(unittest, `python3 -I`) — 픽스처마다 기대 항목 id·수준 단언. CI `data` job 에 1줄 추가는 메인 세션 — 결과 절에 YAML 1줄 적는다.
  - `q5_probe/probe_import.gd:17,23,35,40` 루프 변수 타입 힌트(`for i: int in …` 등) 보정.
- 제외(다른 티켓): Godot 임포트 단계(`EditorScenePostImport`)·게임 데이터 등록 → SE-041. 실제 에셋 생성 → SE-041. 린터를 commit hook 에 거는 것 — 보류(검수 큐 진입 시 수동 실행 + CI 단위 테스트로 충분).
