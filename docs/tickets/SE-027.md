## 목표

`.glb` + `META.json` 한 쌍을 받아 GLTF_SPEC §10 의 L1~L10 을 판정하는 헤드리스 린터(표준 라이브러리만, Godot 불필요)를 만든다. 거부(exit 1)/경고(exit 0) 결과를 `project/assets/review-queue/<asset-id>/lint.json` 에 항목 id 별로 남긴다. 이 린터가 있어야 SE-041 의 첫 슬롯 서피스 에셋이 검수 큐에 들어갈 수 있다(PRD "자동 검사(폴리곤 수, 피벗 위치, 스케일, 머티리얼 슬롯)").

## 범위

- 포함:
  - `tools/assets/lint_gltf.py <asset.glb> <META.json> [--out <lint.json>] [--config tools/assets/lint_config.json]` — L1~L10 전부 + 덧붙임 3건(`NORMAL` 존재: 거부, 미사용 머티리얼: 경고, `extensionsRequired` 비어 있음: 거부). 메시지 형식은 §3 표(파일명·머티리얼 이름·primitive 번호). 종료 코드: 0 통과(경고 포함) / 1 거부 / 2 인자·파일 오류.

### META.json 필드 (SE-028 이 이김)

티켓 범위 문구의 `category: furniture_small|furniture_large|character|lod1` 은 SE-028 확정 스키마와 충돌한다. SE-028 에서 `category` 는 가구 7종 enum(`stage`…`decor`), 예산 칸은 별도 필드 `poly_budget`(`furniture_small`|`equipment_large`)이다. 그래서 META.json 을 `{asset_id, ticket, category, footprint, height_m, poly_budget}` 6키로 정했다. `category` 는 가구 7종 + 가구가 아닌 에셋용 `character`, `poly_budget` 은 SE-028 두 값 + 린터가 더한 `character`·`lod1`. L8 은 `poly_budget`, L10 은 `category` 또는 `poly_budget` 이 `character` 일 때 적용.

### 열린 질문

1. `poly_budget` 에 `character`·`lod1` 을 더하고 `category` 에 `character` 를 더한 것(위). SE-028 `furniture.schema.json` 의 `poly_budget` enum 은 가구용 두 값만이라 가구 행에는 영향이 없다. 캐릭터·LOD1 에셋 티켓이 생기면 그쪽 데이터 모델과 맞출 것. 추천: 현행 유지.
2. 외부 `uri` 를 가진 buffer 는 거부(exit 1)가 아니라 입력 오류(exit 2)로 처리했다(버퍼를 읽을 수 없어 다른 검사를 못 하므로). GLTF_SPEC §1 의 "외부 .bin 금지" 와 결과가 다르지 않다(검수 큐 진입 불가). 거부 항목으로 바꾸려면 L-번호를 정해야 한다. 추천: 현행 유지.
3. `A1`~`A3` 은 티켓 범위의 "덧붙임 3건" 에 L-번호가 없어 새 id 를 붙였다.
4. 수치(검토 필요): `lint_config.json` 의 `tolerance.footprint_m` 은 SPEC 에 별도 값이 없어 피벗 허용 오차와 같은 0.01 m 로 뒀다.
5. Blender 실물 내보내기 `.glb` 로 검증하지 못했다(환경에 Blender 없음, SE-019 §9 한계와 동일). 첫 실제 에셋(SE-041)에서 린터가 정상 에셋을 거부하지 않는지 확인 필요: 특히 Blender 가 넣는 `KHR_materials_*`·`extras`·노드 `rotation` 항등 쿼터니언·`-0`.
