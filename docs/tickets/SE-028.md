## 목표

sim-engineer 가 질문 없이 build 시스템(SE-032)을, render-engineer 가 배치 UI(SE-037)를, art-pipeline 이 에셋(SE-041)을 시작할 수 있는 단일 출처를 만든다: 티어 1 맵(24×24 지하 클럽 — 벽·입구·바닥 영역), 가구 20종의 역할과 수치, 배치 규칙(유효/무효 판정), 커버리지 공식(음향·시야·바 서비스·수용 인원·피난), 그리고 build ↔ economy 핸드셰이크와 `build.*` 이벤트 전부.

## 범위

- 포함:
  - `docs/gdd/build.md` — 절 형식(목적 → 규칙 → 수치표 → 수용 기준 → 테스트 방법 → 열린 질문). 규칙: (1) 맵: 24×24, 고정 벽(외곽 + 지하 기둥 몇 개), 입구 타일 1~2개(고정, 철거 불가), 바닥 전체 배치 가능 영역; 맵은 데이터(`project/data/maps/tier1_club.json`)로. (2) 가구 20종 카테고리: 무대(1종 이상, 크기별), 음향(스피커·모니터), 조명(스포트·무빙 헤드 — 연출 등급), 바(카운터·냉장고 `glass`), 편의(화장실·물품보관·벤치), 안전(소화기·비상구 표지·출구 확장), 장식(포스터·네온 `emissive`). 각 가구: `id, name, category, footprint [w,d], height_m, build_cost, upkeep_per_day, rotatable, wall_required(bool), effects` — `effects` 는 커버리지 입력(`sound_radius`, `sight_block`, `bar_service_radius`, `capacity_add`, `evac_capacity`, `satisfaction_bonus_bp`, `light_grade`). **`model` 필드(선택, `res://assets/models/<id>.glb` 경로 — SE-041 에셋 등록용, v0 는 전부 비움)** 를 스키마에 예약한다. 슬롯 팔레트는 Q1 추천대로 `slots: {base, accent, emissive, glass}` 색 id(팔레트 미정이면 hex 임시값). (3) 배치 규칙 B1~Bn: 맵 안·점유 겹침 없음·벽 필요 가구는 벽 인접·입구 차단 금지(입구에서 무대 앞까지 경로 존재)·무대는 1개만(v0)·회전 0/90/180/270·철거 환불 `demolish_refund_rate_bp`(economy). (4) 커버리지 공식: 음향 = 스피커·무대 반경 안 관람 타일 비율, 시야 = 무대 가시 관람 타일(시야 차단 가구 뒤 제외, 직선 레이캐스트 타일 단위), 바 서비스 = 바 반경 안 타일 비율, 수용 인원 = `min(tiers.capacity_max, 바닥 자유 타일 × 타일당 인원 + Σ capacity_add)`, 피난 용량 = Σ evac_capacity(수용 인원 초과 시 만족도 감점 입력 — show.md 로 넘김). 결과는 `build.coverage_changed` 이벤트 + 관람 타일 집합(관객 시스템 입력). (5) 핸드셰이크: `build.place_requested` → 유효성 → `economy.charge_proposed {reason:"build"}` → `charge_resolved.approved` → `build.placed`, 아니면 `build.rejected {reason}`; 철거 `build.demolish_requested {entity_id}` → `build.demolished` + `economy.refund_proposed`; 설치 목록 변경마다 `economy.upkeep_reported {total}`. 낮 구간에서만 배치·철거 허용(P2 와 같은 규칙), 그 밖은 `build.rejected {reason:"not_allowed"}`. (6) 스냅샷: `systems.build` = 설치 인스턴스 목록(`entity_id, furniture_id, cell, rotation`) + 다음 entity 번호. 결정성: build 는 난수를 쓰지 않는다.
  - `project/data/furniture/furniture.json`(version 1, rows 20) + `project/data/schemas/furniture.schema.json`; `project/data/maps/tier1_club.json` + `maps.schema.json`; `tools/validate_data.py` 가 자동으로 집는지 확인(스키마 이름 규칙) — 안 집히면 결과 절에 "메인 세션 1줄" 로.
  - `docs/gdd/events.md` 에 `build.*` 행 확정(골격 행 교체): `build.place_requested`, `build.demolish_requested`, `build.placed`, `build.rejected`, `build.demolished`, `build.coverage_changed`. 페이로드는 E4 규칙(명령 숫자 `int`).
  - 수용 기준 절(sim-engineer 가 테스트로 옮길 BC1~BCn): 유효/무효 케이스 표(최소 8), 커버리지 기준 배치 2개(빈 방 / 기준 배치 "무대 1 + 스피커 2 + 바 1 + 벤치 2" 의 커버리지·수용 인원·유지비 기대값 리터럴), 환불·유지비 규칙(모든 가구 `⌊build_cost × 0.3⌋ > upkeep_per_day`), 20종 합계 건설비가 `starting_cash`(5,000)로 "무대 + 스피커 1 + 바 1" 은 살 수 있고 전부는 못 사는 범위.
  - 열린 질문은 추천안을 적고 **추천안을 데이터에 넣는다**(사람 결정 항목 없음 — 룩·팔레트 값은 임시 hex, 팔레트 티켓에서 교체).
