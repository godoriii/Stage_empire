## 목표

저녁 진입에 오늘 입장 수를 결정적으로 뽑고(`audience` 스트림), 에이전트를 틱마다 상태 기계로 돌려(입장·이동·관람·바·퇴장) 공연 끝에 `audience.day_summary` 와 `economy.sales_reported` 를 낸다. 틱마다 `audience.agent_moved` 로 위치를 알린다(view 보간용). 150명 × 10 tick/s 헤드리스 한 틱 ≤ 2 ms.

## 범위

- 포함: `project/sim/audience_config.gd`, `project/sim/audience_system.gd`(`AudienceSystem`: `update(ctx)` 에서 상태 기계 1스텝 — `system_order` audience 는 artist 뒤·show 앞), 에이전트는 Dictionary 배열(기본형, id 오름차순 순회), `TilePath` 질의는 경로 캐시(한 에이전트당 목표 변경 시만), 짝 테스트 2개 + 성능 테스트 1건(헤드리스 900틱 × 150명 벽시계 측정 — 임계는 qa 리포트 기록용, 단언은 느슨하게 ≤ 5 ms/틱).
- 제외(다른 티켓): 렌더(SE-038), 흐름장, 스태프 대기열, 홍보, show 산식(SE-035 — 이 티켓은 에이전트별 `satisfaction_bp` 누적과 평균만).

### 구현 결정 (결정 로그 후보, SE-032·SE-033 선례)

1. **D1 `today.left_totals`(스펙에 없는 10번째 키)** — UP5 가 `gone` 을 즉시 지우므로 공연 끝(FN2·SF9·`avg_components`·`by_type`)에는 조기 퇴장자 레코드가 없다(audience.md 는 "요소를 레코드에 따로 저장하지 않는다"고 하지만 레코드 자체가 사라진다). P1 확정 때 `{satisfaction_bp, lineup_bp, sound_bp, sight_bp, value_bp, wait_bp, by_type: {<유형>: {left_early, satisfaction_bp}}}` 합을 `today.left_totals` 에 더하고 스냅샷에 넣었다(복원 동치 유지). RU4 는 10키를 검사한다. → 열린 질문 2.
2. **D2 경계 테스트 정규식** — `test_core_boundary.gd` 의 난수 검사가 `randi\(` 를 통째로 금지해 스펙이 요구하는 `rng.stream("audience").randi()`(R1)까지 막았다. tick.md "금지 (sim·core·world)" 표("전역 `randi()`… → `tick_loop.rng.stream(...)`")대로 앞에 `.` 이 없는 전역 호출과 `RandomNumberGenerator` 만 걸도록 좁히고, 검사기 자체 확인 2줄(전역 4종은 걸림, 스트림 `.randi()` 는 통과)을 더했다. audience 쪽은 `test_source_boundaries` 가 "스트림 호출은 `STREAM` 의 `.randi(` 두 곳뿐, `randf`·`randi_range` 0"을 따로 고정한다.
3. **D3 커버리지 입력 검사 = RU2** — 이벤트로 받은 좌표도 맵 안이어야 하고 `capacity`·`satisfaction_bonus_bp` 는 0 이상 정수여야 받는다(아니면 `push_warning`, 무시). 맵 밖 좌표를 받아 두면 자기 `snapshot()` 이 RU2 로 거부되어 SH3 이 깨지기 때문(SE-044 의 build `phase` 검사와 같은 이유). 정수값 float 는 `JsonUtil` 로 int 로 접는다.
4. **D4 입력 페이로드 방어** — `time.phase_changed`(`to ∈ SimConfig.PHASE_IDS`, `day` int ≥ 1), `time.day_started`, `reputation.changed`(`total` int ≥ 0), `economy.ticket_price_changed`(`price` int ≥ 1)가 틀리면 `push_warning` + 무시(ArtistSystem 선례). LS3 은 스펙대로 `push_error`.
