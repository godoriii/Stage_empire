## 목표

v2 컨셉(운영만으로 도는 로그라이트 프로모터)의 규칙을 **구현자가 그대로 옮길 수 있는 수식**으로 쓰고, 1막(클럽 3공연 + 결산 쇼케이스)을 끝까지 돌릴 수 있는 수치 데이터를 만든다.

## 범위

- 포함: 런·막 진행, 제안 카드, 준비 5기둥(장소·라인업·시설·인력·티켓/홍보), 개최 시뮬(시간 구간별 숫자 모델), 돌발 카드, 결과 원인 분해, 보상 카드 풀·등급, 런 실패/클리어 조건. 1막은 확정 수치, 2·3막·피날레는 대략치.
- 제외: 메타 해금 상세(SE-070 이후), 관람 화면 룩, Godot 구현.

## 수용 기준

- [ ] AC1. `docs/gdd/v2/` 에 run.md·show.md·events.md·rewards.md 가 있고, 모든 수식이 의사코드로 적혀 있다(정수 연산, 시드 RNG 호출 위치 명시).
- [ ] AC2. 데이터 `docs/gdd/v2/data/*.json`: acts, venues, artists, facilities, staff, events, rewards, balance. 매직 넘버는 전부 여기에 있다.
- [ ] AC3. 결과의 만족도 감점이 원인별 항목으로 나뉘고, 각 원인이 준비 결정 하나에 대응한다(표로 명시).
- [ ] AC4. 손 계산 예시 2개(잘 준비한 공연 / 화장실·보안 부족 공연)의 전 과정 숫자가 문서에 있다. SE-069 엔진의 고정점 테스트로 쓴다.
- [ ] AC5. 보상 카드 50장 내외, 등급 5단계(노멀 55 / 스페셜 25 / 레어 13 / 유니크 6 / 레전더리 1, 막별 상향표 포함).

## 테스트 방법

- SE-069 엔진이 AC4 예시를 그대로 재현하는지로 확인. JSON 은 `python3 -m json.tool` 로 문법 확인.
