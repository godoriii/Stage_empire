## 목표

rng 상태가 깨진 스냅샷을 `TickLoop.restore()` 에 넣으면 `push_error` 가 2회 난다: `SeededRng.set_state`(`project/core/rng.gd:66`·`:70`) 1회 + `TickLoop._restore_fail("rng 상태 적용 실패")`(`project/core/tick.gd:228`) 1회.
tick.md `:360` "정확히 1회"와 글자로는 어긋나지만 SE-001 구현 그대로이고, SE-012 EC16 (c) 의 `TickLoop` 경로도 같은 결로 "시스템 1 + TickLoop 1 = 2회"를 단언한다(`test_economy.gd:986-987`).
**코드를 바꾸지 않고** 규칙을 "TickLoop 자신의 `push_error` 는 1회; `SeededRng.set_state`·시스템 `restore_hook` 이 내는 것은 별도(합계는 1 + 하위 구성 요소 수)"로 명문화하고, rng 오류 케이스 테스트 1개로 고정한다.

## 범위

- 포함(1차, game-designer — `docs/gdd/tick.md`):
  - #스냅샷 `restore` 문단(`:360`)을 "각 검사 단계에서 처음 걸린 조건 하나로 실패하고 **`TickLoop` 자신의** `push_error` 는 정확히 1회다. 하위 구성 요소가 내는 `push_error`(4(b) `SeededRng.set_state`, 5·7단계 시스템 `restore_hook`·롤백)는 별도로 더해진다(예: rng 상태 오류 = 2회, 시스템 restore 실패 = 시스템 1 + TickLoop 1 = 2회)" 로 고친다.
  - 수용 기준 표의 관련 행(restore 거부, SE-009 AC10 행 등)에 "`push_error` 1회" 가 `TickLoop` 자신 기준임을 한 번만 적는다. economy.md EC16 (c) 와 일치시킨다(economy.md 는 수정 안 함 — 이미 2회 규칙).
  - 변경 이력 행 1개(SE-017). 수치·이벤트·스냅샷 키 변경 없음.
