## 목표

SE-001 구현(`EventBus.publish()`가 `*_requested` 페이로드의 float 를 정수값이어도 거부)이 tick.md v0·events.md·economy.md 와 어긋난다.
reviewer(docs/reviews/SE-001.md 발견 1)가 **스펙을 구현에 맞추는 (a)안**을 채택했다. 근거: float 허용은 JSON 왕복·복원 후 상태 해시 동일 규칙(tick.md 스냅샷 절)과 자기모순이고, 강한 계약을 먼저 병합하고 완화하는 순서가 안전하다.
이 티켓이 닫히기 전에는 economy 구현 티켓을 내지 않는다(economy.md 의 25.0 허용 문장을 그대로 구현하면 EC13 이 실패).

## 범위

- 포함: tick.md, events.md, economy.md 의 문장 수정과 변경 이력. SE-001 결과 절·docs/reviews/SE-001.md 발견 1·2 의 내용 반영.
- 제외(다른 티켓): core/tests 코드 변경 0 (코드는 이미 맞다). SE-007-bug(별도).

## 수용 기준

- [ ] AC1. tick.md E4 에 "명령 페이로드 숫자는 int 만. float 는 정수값(2.0)이어도 `publish()`가 `push_error` + `false`, 큐에 넣지 않음. 상태 이벤트는 float 허용" 문장이 있다.
- [ ] AC2. tick.md 배속 요청 처리 표 1행에서 "정수값 float 인정"이 사라지고 "float 는 버스가 먼저 거부(핸들러 도달 없음)"로 바뀐다.
- [ ] AC3. tick.md restore 절: 5단계가 "pending_commands 안의 정수값 float → int 재귀 정규화, 정수 아닌 float 가 있으면 복원 실패(상태 불변)"로 확정되고, 3단계 검사 목록에 I4(`speed ∈ speeds`)와 seed 범위(0~2^31−1)가 추가된다.
- [ ] AC4. tick.md 수용 기준 표의 `test_speed_rejected_keeps_state` 1.5 행이 "publish false + push_error 1회, `time.speed_rejected` 없음, 상태 해시 불변"으로 바뀌고, AC8 에 `test_event_bus.gd::test_command_payload_numbers_int_only` 행이 추가된다.
- [ ] AC5. events.md 의 `time.speed_requested`·`economy.ticket_price_requested` 행에서 "(정수값 float 허용)"이 사라지고, 규칙 절에 "명령 페이로드 숫자는 int 만(tick.md E4)" 한 줄이 있다.
