### 구현 판단(리뷰어 참고)

1. **측정기 판정 조건은 "요청 시안" 기준.** 티켓 문구 `spike.material_id != PLAIN_ID and spike.crowd.material_override == null` 을 그대로 쓰면, 같은 티켓의 스파이크 폴백(실패 시 `spike.material_id = PLAIN_ID`)과 함께 조건이 영원히 거짓이 된다. 그래서 왼쪽 항을 측정기 자신의 `material_id`(= 요청 시안, `spawn` 에서 `wanted_material` 로 확정)로 읽고, 폴백 여부(`spike.get_material_id() != material_id`)를 OR 로 더했다. 대조군 테스트로 plain(잘못된 경로여도 로드 대상 아님)과 정상 b 는 통과함을 고정.
2. **AC6 은 `grid_sandbox.gd` 를 고치지 않고** 테스트에서 리소스 캐시를 잠시 가로챘다: `toon_a.tres` 경로를 빈 `Resource` 로 `take_over_path` → `ShaderVariants.load_material("a")` 가 `as ShaderMaterial` null → `apply` −1 → `apply_material("a") == false`. 끝나면 원래 리소스로 `take_over_path` 복원(`after_each` 안전망 포함), 같은 호출이 true 가 되는 대조군까지 한 테스트에서 확인. 티켓 "쓰는 폴더" 에 `grid_sandbox.gd` 가 없고 SE-018 리뷰 발견 2 가 "샌드박스에 path_pattern 을 뚫지 말 것" 을 권해 이 방법을 택했다. 가짜 리소스 참조를 멤버로 쥐어야 한다(지역 변수면 해제되며 캐시 항목이 사라져 디스크에서 다시 로드된다 — 첫 시도에서 확인).
3. 스파이크·측정기의 로드 실패 주입은 `material_path_pattern`(기본 = `ShaderVariants.MATERIAL_PATH_PATTERN`, 존재하지 않는 `res://tests/view/missing_params/toon_%s.tres` 로 바꿈) — `ShaderVariants.apply*()` 의 기존 `path_pattern` 인자를 그대로 쓴다.
