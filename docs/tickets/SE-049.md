## 목표

공연 중에 저장한 게임을 불러오면 스포트가 다음 공연까지 꺼진 채 남는다(`show.started` 가 다시 오지 않음). 이벤트 계약을 깨지 않고 view 가 로드 직후 공연 상태를 복구하게 한다.

## 결정 (producer, SE-038 reviewer 추천 채택)

- `show.started` 재발행은 쓰지 않는다: 하루 0~1회 계약을 깨고, reputation 이 이 이벤트로 `show_day`·`show_genre` 를 쓴다.
- `time.phase_changed` 재발행도 쓰지 않는다: economy 정산·build sync·artist 라인업이 다시 반응한다. 또 단계가 show 여도 공연이 없는 날(`show.skipped`)이 있다.
- **`session.loaded {day, phase, speed, show_active}`** 로 확장한다. `show_active` 는 그날 `show.started` 가 났고 아직 `show.ended` 전이면 true.

## 범위

- 포함(game-designer): events.md `session.loaded` 페이로드 4필드, show.md 에 `show_active` 정의(show 시스템 상태에서 읽는 값), tick.md 재발행 표에 순서(`session.loaded` → `build.placed` 재발행 …).
- 포함(sim-engineer): `GameSession` 이 로드 성공 뒤 4필드를 채워 발행(show 시스템 읽기 전용 접근자), 테스트.
- 포함(render-engineer): `StageLights` 가 `session.loaded.show_active` 를 기억하고, 뒤따르는 `build.placed` 재발행으로 Σ light_grade 가 쌓일 때마다 켤 개수를 다시 계산. `CrowdView` 는 `session.loaded.speed` 를 초기 배속으로.
- 제외: 그 밖의 view 복구.

## 수용 기준

- [ ] AC1. 공연 중(show 구간, 공연 있음) 스냅샷 → 로드 → 첫 프레임 뒤 켜진 스포트 수 = 저장 시점과 같음. → e2e 테스트
- [ ] AC2. 공연 없는 날(show 구간, `show.skipped`) 로드 → 스포트 0. 낮·저녁 로드 → 0. → 테스트
- [ ] AC3. 로드 후 이벤트 열에 `show.started`·`time.phase_changed` 재발행 0건(reputation·economy 상태 불변 해시). → 테스트
