## 목표

SE-036 코드와 SE-039 가 정한 `session.*` 계약이 6곳 다르다. producer 결정: **코드가 계약을 따른다**(계약 변경 없음). SE-040 이 UI 와 세션을 붙이기 전에 맞춘다.

## 결정 (producer, SE-036 reviewer 추천 채택)

- `session.save_failed` 는 쓰지 않는다. SN3 대로 저장 실패는 `push_error` 만(UI 는 `session.saved` 가 안 오면 아무것도 표시하지 않는다 — MVP 범위). 필요해지면 계약을 바꾸는 별도 티켓.
- 불러오기 실패 사유는 SN4 의 5종과 판정 순서 그대로.
- 새 게임 명령 `session.new_game_requested {seed}` 와 SN5(버스 구독 유지)를 이 티켓에서 구현한다 — SE-040 은 이 명령만 발행한다.

## 범위

- 포함(sim-engineer, `project/core/game_session.gd` + 테스트)
  - `load_failed.reason`: `invalid`/`missing`/`corrupt`/`version_mismatch`/`restore_failed`, SN4 순서. `bad_slot`·`not_found` 제거.
  - `session.save_failed` 발행 제거(SN3).
  - 슬롯 형식 SN1 `^[a-z0-9_]{1,24}$`(`is_valid_filename` 대신). 키가 없으면 `load_failed.slot` 은 `null`.
  - SN2: 불러오기·새 게임 성공 뒤 같은 경계에 남은 명령 폐기. 실패한 불러오기는 큐 불변.
  - SN5: `session.new_game_requested {seed}` 처리 — 같은 `GameSession`·같은 `EventBus` 로 세계를 새로 만들고(구독 유지), `session.loaded {day:1, phase:"day", …}` + AC6 재발행. 같은 seed → `new_game(seed)` 와 같은 1일차 상태 해시.
- 포함(qa): 계약 ↔ 코드 키·열거 대조 테스트(events.md 를 파싱해 reason 열거 비교), 변이.
- 제외: UI 변경(SE-040), 데이터 필드(SE-057).
