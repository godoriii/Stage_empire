## 목표

제품 코드는 맞는데 테스트가 없는 분기 세 곳을 테스트로 고정한다. 제품 코드·데이터 변경 **0**.
1. `TickLoop.restore()` 5단계 ④ — 훅 시스템 객체가 해제돼 `Callable.is_valid()` 가 아닌 상태(`tick.gd:243-244`). tick.md 표 2행이 "고정하는 테스트" 로 `test_restore_rejects_bad_snapshot` 을 적었지만 그 테스트는 5단계 ①②③만 때린다(reviewer SE-017 발견 1: 표가 ④ 에 대해 과장).
2. 파산 뒤 잘못된 `time.phase_changed` 페이로드 — economy.md 는 두 이벤트 모두 "파산 전과 같은 페이로드 검사" 라 했는데 EC12 테스트는 `time.day_started {day: "x"}` 만 단언한다(`test_economy.gd:722-724`).
3. 파산 뒤 `_on_day_started` 의 `if bankrupt: return` 위치 — `pending_bailout == null` 이라 정상 진행에서는 관측 불가. `restore()` 로 `bankrupt: true` + `pending_bailout != null` 상태를 만들면 return 위치 변이에 민감한 단언이 된다(reviewer SE-016 참고 1).

## 범위

- 포함(1차, sim-engineer):
  - `test_tick.gd`: 새 케이스(새 함수 `test_restore_rejects_invalid_hook` 권장 — 기존 `test_restore_rejects_bad_snapshot` 의 `errs` 누적과 섞지 않는다). 절차: `loop = _new_loop()`, `journal = []`, `gone = FakeSys.new("build", journal)`, `register_system("build", gone.update, gone.snapshot_hook, gone.restore_hook)`, `good = loop.snapshot()`(이 시점 `systems.build` 가 있음을 전제 단언), `fields0 = [loop.tick, loop.rng.get_state(), loop.bus.get_pending_commands()]`, `gone = null`(`test_tick.gd:794-796` 수법) → `assert_false(loop.restore(good))`, `assert_push_error_count(1)`(리터럴 1 — `TickLoop` 자신, 하위 0), `[loop.tick, loop.rng.get_state(), loop.bus.get_pending_commands()] == fields0`, `journal == []`(`restore_hook` 0회), 메시지 단언 `assert_push_error("더 이상 유효하지 않다")`. 상태 해시는 `snapshot()` 이 `{}` 를 돌려주므로 `_hash(loop)` 대신 `fields0` 비교로(결과 절에 그 이유 1줄).

(= `_on_day_started` 의 return 위치를 `_accept_bailout(true)` 뒤로 옮기는 변이에서 실패하는 단언.) qa 가 그 변이를 SE-023 스크립트(또는 사본)로 확인한다.
