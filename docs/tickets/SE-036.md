## 목표

시스템 7개(build·artist·audience·show·economy·reputation + TickLoop)를 `system_order` 순서로 만들고 등록하는 단일 조립점 `GameSession`(RefCounted)과, 그 스냅샷을 파일로 쓰고 읽는 `SaveFile`(core)을 만든다. 마감(close 진입)마다 오토세이브. 티어 1 루프 30일이 헤드리스에서 돌아가고(기준 배치 + 매일 섭외), 중간 저장·로드 뒤 진행이 연속 진행과 동일함을 리플레이 테스트로 고정한다. 이 티켓이 끝나면 "루프가 돈다" 가 헤드리스로 입증된다.

## 범위

- 포함:
  - `project/core/game_session.gd`(`GameSession`: `new_game(seed, data_root := "res://data")`, `step(delta_s)`/`advance(n)` 위임, `bus`, 시스템 읽기 전용 접근자, `snapshot()`/`restore()` 위임, `save_to(path) -> bool`/`load_from(path) -> bool`, 오토세이브 경로 규칙 `user://saves/autosave_day<N>.sav`(보관 수는 `sim.json` 또는 새 `save.json` 필드 — game-designer 요청: 결과 절에 필드 이름·기본값 3 제안, 수치는 넣지 않고 티켓을 돌려보낸다), 명령 이벤트 `session.save_requested {slot: String}`·`session.load_requested {slot}`(events.md 등록은 결과 절 문구 → SE-039 와 함께 game-designer 1줄)).
  - `project/core/save_file.gd`(`SaveFile`: `write(path, snapshot) -> bool`(JSON → gzip, `FileAccess` 는 Node 아님), `read(path) -> Dictionary`(`{}` 실패), 헤더 `{save_version: 1, snapshot_schema_version, written_day, app_commit?}`, 손상·버전 불일치 → `push_error` + `{}`).
  - `project/tests/sim/test_game_session.gd`, `test_save_file.gd`, `replay/test_replay_tier1_loop.gd`(30일 시나리오 봇 명령 열: 1일차 기준 배치 설치 → 매일 낮 로컬 밴드 섭외 → close 에서 next_day; 15일차 close 에 저장 → 새 세션 로드 → 30일까지; 연속 진행과 상태 해시·이벤트 열 동일).
  - 시스템 생성·구독 순서 = `system_order`(tick.md), 등록 실패 시 `new_game` 실패(`push_error`, `false`).
- 제외(다른 티켓): UI(SE-039/SE-040), 마이그레이션 함수(버전 1 뿐 — 틀만), 클라우드·슬롯 UI, 봇 정책 일반화(SE-042 — 이 티켓의 30일 명령 열은 테스트 고정 데이터).
