## 목표

사람 플레이 테스트(SE-043) 전에 "10분(≈ 3일) 안에 무언가 결정할 거리가 생기고, 30일 안에 티어 2 가 보이며, 멍청한 정책은 파산한다" 를 숫자로 본다. game-designer 가 봇 정책 3종(절약형·공격형·무작위)과 대리 지표(예: 3일차까지 현금 변동 폭, 첫 흑자일, 만족 등급 분포, 명성 500 도달일, 파산율, 결정 분기 수 — "한 번 더" 를 직접 재지는 못하므로 **대리**임을 명시)와 목표 범위를 정하고, qa 가 헤드리스 봇 러너로 시드 100개 × 정책 3 을 돌려 표를 낸다. 범위 밖이면 밸런스 티켓(game-designer)을 producer 가 발행한다 — 이 티켓은 측정만.

## 범위

- 포함(1차): `docs/gdd/bot_metrics.md` — 정책 3종의 결정 규칙(낮: 무엇을 사고 누구를 섭외하나, 가격, 배속은 무관), 대리 지표 ≥ 6 과 각 목표 범위·근거, 통계 형식(중앙값·사분위·파산율), 시드 수(100), 일수(30), 결과 파일 형식(`docs/reports/SE-042.md` 표 + `tools/bot/results/SE-042.json`).
- 포함(2차): `tools/bot/play_bot.gd`(`extends SceneTree`, `godot --headless --path project -s res://../tools/bot/play_bot.gd` 가 안 되므로 **`project/tests/e2e/bot_runner.gd`** 에 러너를 두고 `tools/bot/play_bot.sh` 가 호출 — qa allow 둘 다), 정책 구현은 데이터(`tools/bot/policies/*.json`)에서 읽음, `GameSession` 을 헤드리스로 N판, 결과 JSON·마크다운 표, 실행 시간(100 × 3 × 30일 — 예상 ≤ 10분; 초과하면 시드 30 으로 줄이고 기록). 단위 테스트 `project/tests/e2e/test_bot_runner.gd`(정책 1·시드 1·3일 → 결정적, 지표 키 전부 존재).
- 제외(다른 티켓): 밸런스 조정(후속 game-designer 티켓), 1,000판(프로덕션), UI 자동화(봇은 sim 명령만), CI 상시 실행(수동·마일스톤 관문 때만 — 결정 로그).
