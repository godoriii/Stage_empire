# SE-003 성능 스파이크: 인스턴싱 캐릭터 5,000 + 동적 라이트 32, 60fps 측정

| 마일스톤 | 프리프로덕션 |

## 목표

ADR-0001 의 조건부 결정을 확인한다. Godot 4.6 forward_plus 에서, 매 프레임 움직이는 로우폴리 캐릭터 5,000개(GPU 인스턴싱)와
매 프레임 움직이는 동적 라이트 32개가 **모두 화면 안에 보이는 상태로** 1080p 평균 60fps 가 나오는지 재현 가능한 절차로 측정하고 표로 남긴다.
통과/실패 판정은 숫자로만 한다. 실패 시 Unity 재검토는 사람의 결정이며 producer 가 ADR 티켓을 만든다. 이 티켓은 결론을 내리지 않고 측정만 한다.

## 범위

- 포함:
  - `project/view/perf/spike_crowd.tscn` + `spike_crowd.gd` — `MultiMeshInstance3D` 캐릭터 프록시(캡슐+박스 조합, ≤ 800 tri) 5,000개를 100×100m 평면에 배치. 매 프레임 CPU 에서 전 인스턴스 트랜스폼 갱신(실제 게임에서 sim 위치를 보간해 쓰는 경로와 같은 비용). `OmniLight3D`/`SpotLight3D` 혼합 32개, 매 프레임 위치·색 변화. 바닥·카메라는 SE-002 의 것. 인스턴스 수·라이트 수·셰도우 라이트 수는 씬의 `@export` 변수.
  - `project/view/perf/perf_stats.gd` — 프레임 시간 배열 → 평균 fps, 1% low fps, 평균/최대 프레임 ms 계산(순수 함수, 헤드리스 테스트 가능).
  - `project/tests/view/perf/measure_spike.gd` — `godot --path project res://view/perf/spike_crowd.tscn -- --measure --config=B` 로 실행 시: VSync 끄기(`DisplayServer.window_set_vsync_mode`), 1920×1080 창, 10초 예열, 30초 측정, `user://perf/SE-003_<config>.json` 저장 + 콘솔 표 출력. 키: `config, instances, lights, shadow_lights, avg_fps, p1_low_fps, avg_frame_ms, max_frame_ms, draw_calls, primitives, resolution, vsync, renderer, gpu, cpu, godot_version, commit`.
  - `project/tests/view/perf/results/SE-003.md` — 아래 구성 A~D 의 결과 표 + 측정 PC 사양.
  - `project/tests/view/test_spike_scene.gd`, `project/tests/view/test_perf_stats.gd`.
- 제외(다른 티켓):
  - 실제 캐릭터 모델·스켈레톤 애니메이션(art-pipeline), 임포스터·군중 셰이더(티어 4+ 티켓).
  - 툰 셰이더 적용 상태의 비용 — SE-004 에서 이 씬을 재사용해 측정.
  - 최소 사양(Intel Iris Xe 30fps) 측정 — 해당 하드웨어가 있을 때 사람 실행. 없으면 "검증 불가"로 기록.
  - 통과/실패에 따른 ADR 작성 — producer.

## 수용 기준

- [ ] AC1. 씬이 헤드리스로 로드되고 `MultiMesh.instance_count == 5000`, `Light3D` 노드 수 == 32, 그중 `shadow_enabled == true`가 구성 B 기본값으로 8개, 인스턴스 메시 삼각형 수 ≤ 800. → `test_spike_scene.gd::test_counts_match_spec`, `::test_instance_mesh_within_tri_budget`
- [ ] AC2. 가시성 보장: SE-002 카메라 최대 줌아웃에서 5,000개 인스턴스 위치 전부가 `Camera3D.is_position_in_frustum() == true`(컬링으로 숫자를 깎지 않는다). → `test_spike_scene.gd::test_all_instances_in_frustum`
- [ ] AC3. 인스턴스 애니메이션: 60프레임 진행 후 인스턴스 트랜스폼의 99% 이상이 0프레임과 다르다. → `test_spike_scene.gd::test_instances_move_every_frame`
- [ ] AC4. 라이트 애니메이션: 60프레임 진행 후 32개 라이트 전부의 위치가 0프레임과 0.01m 이상 다르다. → `test_spike_scene.gd::test_all_lights_move`
- [ ] AC5. `PerfStats.from_frame_times([...])`가 알려진 배열에서 평균 fps·1% low·평균/최대 ms 를 손계산 값과 ±0.01 로 맞춘다(1% low = 느린 쪽 1% 프레임의 평균 fps). → `test_perf_stats.gd::test_stats_from_known_frame_times`
- [ ] AC6. 측정 스크립트 실행이 `user://perf/SE-003_<config>.json`을 위 키 전부로 생성한다. → qa 가 실행 로그와 파일 키 목록으로 확인(GPU 있는 PC 필요, 아래 참고)
- [ ] AC7. 결과 표 `project/tests/view/perf/results/SE-003.md`에 구성 4행이 모두 채워져 있다. 각 행: 평균 fps, 1% low fps, 평균 ms, 최대 ms, draw calls, primitives.

  | 구성 | 인스턴스 | 라이트 | 셰도우 라이트 | 비고 |
  |---|---|---|---|---|
  | A | 5,000 | 32 | 0 | 하한 |
  | B | 5,000 | 32 | 8 (셰도우 아틀라스 ≤ 2048) | **관문 구성** |
  | C | 5,000 | 32 | 32 | 상한 |
  | D | 10,000 | 32 | 8 | 여유 확인 |

  표 상단에 GPU, CPU, RAM, OS, 드라이버, Godot 버전, 커밋 해시, 해상도 1920×1080, VSync off, forward_plus 를 적는다. → qa 리포트에서 대조
- [ ] AC8. 관문 판정이 표 아래 한 줄로 있다: 구성 B 평균 fps ≥ 60 이면 "통과", 아니면 "실패" + CPU/GPU 바운드 분석 한 단락(`Performance` 모니터 수치 근거). 판정을 숫자 외의 말로 흐리지 않는다. → producer 확인
- [ ] AC9. 창 크기·VSync·해상도는 측정 스크립트가 런타임에 설정하며 `project/project.godot`을 바꾸지 않는다. → reviewer(`git diff` 에 project.godot 없음)
- [ ] AC10. `tools/run_tests.sh project/tests/view` 전체 녹색. → qa 리포트 실행 로그

## 테스트 방법

- 헤드리스: `tools/run_tests.sh project/tests/view`
  - `project/tests/view/test_spike_scene.gd` — AC1~AC4 (`SceneTree` 프레임 진행은 헤드리스에서도 `_process`가 돈다)
  - `project/tests/view/test_perf_stats.gd` — AC5
- 측정(GPU 있는 PC, 사람 또는 사람 PC에서 돌린 qa):
  ```bash
  for c in A B C D; do
    godot --path project res://view/perf/spike_crowd.tscn -- --measure --config=$c
  done
  # 결과: ~/.local/share/godot/app_userdata/Stage\ Empire/perf/SE-003_*.json → results/SE-003.md 표로 옮긴다
  ```
  - 에이전트 실행 환경에는 GPU 가 없다. **측정 자체는 사람이 1회 실행**해야 하며, render-engineer 는 자신이 측정할 수 없으면 "결과" 절에 "측정 대기(사람 실행 필요)"라고 적고 표를 비워 둔다. qa 는 사람이 돌린 JSON 을 받아 표와 대조한다.
- 수동 확인: 측정 모드 없이 `godot --path project res://view/perf/spike_crowd.tscn` → 5,000개 캐릭터 프록시가 화면 가득 흔들리고 32개 조명이 색을 바꾸며 돈다. 우상단 fps 라벨.

## 경계 확인

- 쓰는 폴더: `project/view/perf/`, `project/tests/view/` (하위 `perf/`, `perf/results/`)
- 읽기만 하는 폴더: `project/view/camera/`, `project/view/grid/`(SE-002 산출물, 재사용), `docs/style-guide.md`
- 필요한 이벤트(발행/구독): 없음. 스파이크는 sim 과 연결하지 않는다.
- 필요한 데이터 테이블/필드: 없음. 5,000/32/60 은 PRD 의 성능 목표치이지 게임 밸런스가 아니므로 씬 `@export`·측정 스크립트 인자로 둔다. `project/data/`에 넣지 않는다.
- 금지: `project.godot` 수정, 카메라 컬링·LOD 로 인스턴스 수를 깎는 것, VSync 켠 채 측정.
