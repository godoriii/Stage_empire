## 목표

close 구간에 저장한 게임을 불러오면 마감 리포트의 정산 행(R6 매출, R7 비용, R8 순이익)이 0 으로 보인다. 정산 값이 `economy.day_settled` 이벤트로만 나가고 sim 상태에 남지 않기 때문이다. Economy 가 마지막 정산 결과를 스냅샷에 보관하고, `GameSession.hud_state()` 가 그것을 돌려주게 한다.

## 범위

- 포함(game-designer): economy.md #스냅샷에 `last_settlement`(마지막 `day_settled` 페이로드와 같은 키, 새 게임은 빈 값) 1줄, 스냅샷 키 수 갱신.
- 포함(sim-engineer): `Economy` 가 `day_settled` 발행 때 같은 값을 `last_settlement` 로 보관·스냅샷·복원(전부 검사 후 일괄 적용 규칙), `GameSession.hud_state()` 에 포함. 테스트.
- 포함(render-engineer): `day_report.gd` 가 `session.loaded` 뒤 `hud_state().last_settlement` 로 R6~R8 을 채움. 테스트.
- 제외: 정산 공식 변경.

## 결과

### game-designer (2026-10-10)

- 스펙: `docs/gdd/economy.md` #상태(`last_settlement` 행), #정산(S16·이벤트 2), #스냅샷("`last_settlement` 복원" LS1~LS4·검사 ⑦~⑨, "구버전 스냅샷 결정", "표시 접근"), 공개 API 표, 수용 기준 EC2·EC16 (c)·**EC17**(신설), 테스트 방법, 변경 이력. `docs/gdd/tick.md` 변경 이력 1행(Q7 규칙 — 경제 항목 형식 변경 기록).
- 바뀐 테이블: 없음. `economy.json`·`sim.json`·스키마 변경 0. `snapshot_schema_version` 2 유지(아래 결정).
- `python3 tools/validate_data.py --strict`: 14개 테이블, 실패 0, exit 0.

**규칙 요약.** `last_settlement` = 마지막 `economy.day_settled` 페이로드와 같은 19키(전부 int). 새 게임 `{}`. 정산 S16 에서 저장하고, 발행 페이로드는 그 깊은 복사본(같은 순간 — `day_settled` 구독자 안에서 읽어도 같은 값). 다음 날 시작·구간 전환·구제 수락·파산에도 다음 정산 전까지 유지(리포트를 close 에서만 보이는 것은 view 몫). 공식에는 쓰지 않는다. 스냅샷 키 12 → 13(필수 12 + 선택 1), `snapshot()`은 항상 13키.

**AC2 결정 — 구버전 스냅샷(키 없음)은 빈 값 `{}`로 복원(하위 호환), `snapshot_schema_version` 은 올리지 않는다.** 이유: 세이브 파일이 이미 사용자 데이터에 있고(SE-036·SE-040 마감 오토세이브) 마이그레이션 함수가 없어 버전을 올리면 기존 세이브가 전부 `version_mismatch`로 열리지 않는데, 이 필드는 표시용이라 빈 값이어도 현금·대출·파산·명성 진행이 같다. 키가 있는데 형식이 틀리면(LS2: Dictionary 아님, ⑦ 19키 불일치, ⑧ 정수 아님, ⑨ `day != last_settled_day`) 기존 규칙대로 `push_error` 1회·`false`·상태 불변. 이 예외는 공식에 쓰지 않는 필드에만 적용한다(tick.md Q7 은 열린 채).

**sim-engineer 인계**
1. `project/sim/economy.gd`: 상태 `last_settlement: Dictionary = {}`. `_settle`에서 S16 에 페이로드를 만들어 `last_settlement`에 저장하고 `day_settled`에는 `duplicate(true)`를 싣는다(상태 먼저, 발행 나중 — 기존 순서 그대로). `snapshot()`에 `"last_settlement": last_settlement.duplicate(true)` 추가.
2. `_parse_snapshot`: `last_settlement`는 `SNAPSHOT_FIELDS`(필수 목록)에 **넣지 않는다**(넣으면 LS1 이 "필드 누락"으로 거부되고 EC16 (c) 의미가 바뀐다). 필수 12키 검사 뒤 LS1~LS4·⑦~⑨ 검사, 정규화한 값을 다른 필드와 함께 일괄 적용. ⑦의 19키 목록은 페이로드를 만드는 곳과 같은 상수 하나로(이중 정의 금지).
3. `project/core/game_session.gd` `hud_state()`: `"last_settlement": _economy.last_settlement.duplicate(true)` 추가(다른 키 불변).
4. 테스트: `test_economy.gd` EC2 단언 1줄, EC17 (a)(b)(c)(e) — `test_last_settlement_kept_and_restored`(나눠도 됨). `test_game_session.gd` EC17 (d). 기존 테스트 중 경제 스냅샷 키 수·키 목록을 리터럴로 고정한 곳이 있으면 13키로(예: `test_economy_qa.gd`·`test_session_contract_qa.gd` 확인).

**render-engineer 인계**
1. `project/ui/panels/day_report.gd`: `session.loaded` 뒤(현금과 같은 경로, SE-040 AC-39a) `hud_state().last_settlement`를 기존 `economy.day_settled` 저장 슬롯(`S_SETTLED`)과 같은 자리에 넣어 R6(`ticket_revenue`·`bar_revenue`·`revenue`)·R7(`rent`·`upkeep`·`guarantee`·`bar_cost`·`tax`·`loan_repayment`)·R8(`net`)을 채운다. `{}`(새 게임·구버전 세이브)면 지금처럼 0. R8·R12 현금은 그대로 `hud_state().cash`.
2. 테스트: AC1 view 1건 — close 저장 → 로드 → R6~R8 문자열이 저장 시점과 같음. 파일 헤더 주석의 "R6·R7·R8 순이익은 그날 정산 페이로드뿐(결과 절 열린 질문)" 갱신.
