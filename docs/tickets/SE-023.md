## 목표

qa 는 boundary hook 때문에 `project/sim|core|world/*.gd` 를 직접 변이시킬 수 없다(정상). SE-016 qa 는 `project/tests/_mut_tmp/` 에 `project/` 사본을 만들어 변이시키고 GUT 를 돌렸는데, (1) 사본이 untracked 로 남아 reviewer 조건이 됐고 (2) 매 티켓 손으로 반복한다.
한 명령으로 "사본 생성 → 패치 적용 → GUT 실행 → 사본 삭제(항상)" 를 하고 실제 `project/` 는 절대 건드리지 않는 스크립트를 `tools/bot/` 에 둔다.

**정책 확인(producer, 2026-10-09):** `boundary_policy.json` 의 qa allow 에 `tools/bot` 이 **이미 있다**(a955349 셋업 커밋부터). docs/status 후보 표의 "정책 1줄 변경 선행" 전제는 틀렸고, 정책·메인 세션 작업은 **필요 없다**.

## 범위

- 포함(qa):
  - `tools/bot/mutate_and_test.sh <patch.diff> [tests_subdir] [--keep]`:
    - 사본 위치: `$SE_MUTATE_DIR` 이 있으면 그 아래, 없으면 `mktemp -d`(리포지토리 **밖**). `project/tests/_mut_tmp/` 같은 리포지토리 안 경로는 쓰지 않는다(untracked 잔여 방지).
    - 사본: `project/` 를 `.godot/` 만 제외하고 복사(`rsync -a --exclude .godot` 또는 `cp -r` 뒤 삭제). 사본 루트 구조는 `<사본>/project/...` 로 리포지토리와 같게 한다. `tests_subdir` 기본 `tests/sim`(view 는 `tests/view`).
    - 패치: 리포지토리 루트에서 만든 unified diff(경로 `a/project/...` → `b/project/...`, 즉 `git diff` 출력 그대로)를 `<사본>` 루트에서 `patch -p1 --dry-run` 으로 먼저 검사하고 실패하면 exit 3 + `patch` 출력. 통과하면 `patch -p1` 적용. 다른 경로 규칙은 지원하지 않는다(README 에 명시).
    - 실행: `"$GODOT" --headless --path <사본>/project --import` 후 `-s addons/gut/gut_cmdln.gd -gdir=res://<tests_subdir> -ginclude_subdirs -gexit -glog=1`. Godot 바이너리는 `GODOT_BIN` 또는 PATH(`tools/run_tests.sh` 와 같은 규칙, 없으면 exit 4).
    - 종료 코드 = GUT 종료 코드. 요약 줄(`Tests N / Passing M / Failing F`)을 마지막에 다시 출력.
    - 삭제: `trap … EXIT` 로 사본을 항상 삭제(`--keep` 이면 남기고 경로 출력). 실제 `project/` 는 읽기만.
  - `tools/bot/README.md`: 사용법, 패치 만드는 법(`git diff` 를 파일로 — 실제 트리를 고치지 않고 패치를 만드는 법: 사본에서 `git diff --no-index` 또는 손으로 unified diff), 종료 코드 표(0 통과 / GUT 실패 코드 / 3 패치 실패 / 4 Godot 없음), 주의(경계 hook 이 `project/sim` 쓰기를 막는 것은 정상이며 이 스크립트가 그 우회가 아니라 **사본** 검증이라는 한 줄).
  - 예시 패치 2개 `tools/bot/mutations/`: `se016_bankrupt_order.diff`(SE-016 변이 2: `_on_phase_changed`·`_on_day_started` 의 `if bankrupt: return` 을 맨 앞으로 — 기대: `test_bankrupt_after_bailouts_exhausted` 1건 실패) · `se015_range_check_6_off.diff`(SE-016 qa 변이 1: `economy.gd` ⑥ 검사 `if false:` — 기대: `test_restore_rejects_out_of_range` 1건 실패). 각 파일 머리에 기대 결과 주석.
