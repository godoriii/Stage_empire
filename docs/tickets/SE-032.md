## 목표

`build.place_requested`/`build.demolish_requested` 명령을 받아 맵·가구 데이터로 유효성을 판정하고 economy 와 핸드셰이크한 뒤 `build.placed`/`build.rejected`/`build.demolished`/`build.coverage_changed`/`economy.upkeep_reported` 를 내는 순수 데이터 시스템. 관객(SE-034)이 쓸 타일 경로 탐색(점유 타일 차단, 입구 → 목표 타일)도 `world/` 에 둔다. Node·Scene API 0.

### 구현 결정(결정 로그 후보)

1. **H5 확장**: 응답 없는 `pending` 은 `update()` 시작뿐 아니라 **다음 build 명령 처리 시작**에서도 정리한다(같은 경계에 명령 2개 + economy 미등록이면 두 번째 제안이 첫 번째를 덮어쓰지 않게). 결과·경고는 H5 와 같다(`push_warning` 1회 + `rejected · charge_unresolved`). 스펙은 이 경우를 정하지 않았다.
2. **FC3 확장**: `allowed_rotations` 원소가 방향표가 아는 0·90·180·270 밖이면 로드 실패(방향표 없이 풋프린트를 못 계산한다).
3. **tile_kinds 5종 고정**을 로드 검사로 강제(build.md "id 는 5종으로 고정").
4. **H2 `paid`** = `charge_resolved.amount`(정수가 아니면 제안 금액). 현재 economy 는 항상 제안 금액을 돌려준다.
5. 클래스 이름은 티켓대로 `BuildSystem`(build.md 공개 API 표의 `Build`). 그 밖 멤버 이름은 build.md 표와 같다. 의존 방향: world → core 만(`EventBus`, `SimConfig.PHASE_IDS`). `economy.json` 은 `BuildConfig` 가 직접 읽고 `EconomyConfig`(sim) 를 참조하지 않는다.
