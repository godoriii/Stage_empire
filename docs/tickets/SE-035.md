## 목표

공연 구간 시작에 `show.started`/`show.skipped`, 끝에 산식으로 `show.ended {satisfaction_bp, grade, …}` 를 내고, reputation 이 그것으로 장르 벡터·종합 명성을 갱신(`reputation.changed`), 정산 뒤 명성·자금이 임계를 넘으면 `reputation.tier_unlocked {tier: 2}` 를 게임당 1회 낸다. 둘 다 정수·난수 없음·Node 0.

### 결정 (스펙에 없던 것, 선례를 따름)

1. **입장 0 명인 날(F7)**: 스펙 그대로 DS5 → 평균 0 → `disaster`(명성 감소). `test_zero_admissions_day_is_disaster` 가 고정한다. 정책 결정은 SE-042.
2. LN2 확장: 라인업 `genre` 가 `mvp_genres` 밖이면 `push_error`·무시(SS3·`show.started` 계약과 같은 집합 — 복원 불가능한 상태를 만들지 않는다).
3. 입력 페이로드 타입은 `is int` 로 엄격히 본다(SE-033 artist 선례). 스냅샷 복원만 `JsonUtil.as_int` 로 JSON float 를 정규화한다. 형식이 틀린 `time.*` 는 `push_warning`·무시(artist 선례).
4. `compute_result`·`compute_delta` 는 순수 함수라 오류를 내지 않고 `{}` 를 돌려준다(가격 < 1, 모르는 등급·장르, 음수 입장 포함). 시스템 쪽 DS1 `push_error` 는 공개 `summary_error()` 로 같은 검사를 쓴다.
5. `compute_delta.eff_bp` 는 FC1 미충족뿐 아니라 실패 등급(판정 안 함)에서도 −1. `by_genre` 에 없는 장르는 0.
6. `ShowConfig` 는 economy 행 읽기에 `EconomyConfig.from_dict` 를 재사용(티켓 기본가·rate_scale). `ReputationConfig` RL7 은 `max_tier ≥ START_TIER + 1` 도 본다.
7. RP4 의 7행 예 표는 데이터에 없는 문서 예시라 reputation.md 표 값을 그대로 리터럴로 단언했다(그 밖의 기대값은 전부 데이터에서 읽음).
