## 목표

플레이어가 처음 보게 될 화면의 뼈대. 티어 1 부지(24×24m, 1타일 = 1m)가 직교 카메라(피치 약 30°, 요 45°)로 보이고,
마우스를 올린 타일이 강조되며 좌표가 표시된다. 카메라는 팬, 줌 4단계, 90° 단위 4방향 회전만 된다(자유 회전 금지).
이 샌드박스 씬이 이후 성능 스파이크(SE-003)와 셰이더 시안(SE-004)의 공통 무대가 된다.

## 범위

- 포함:
  - `project/view/camera/iso_camera.gd` + `iso_camera.tscn` — `IsoCamera`(Node3D 피벗 + 자식 `Camera3D`). 직교, 피치/요 고정, `rotate_cw/rotate_ccw`, `zoom_in/zoom_out`(4단계), `pan(Vector2)`에 그리드 경계 클램프.
  - `project/view/camera/iso_camera_params.tres` — 줌 4단계 `size` 값, 피치·요, 팬 여유(margin) 등 카메라 상수. 코드에 숫자를 두지 않는다.
  - `project/view/grid/grid_view.gd` — `GridView`. 그리드 크기는 `data/tiers/tiers.json`의 `tier_1.grid_size`, 타일 크기는 `data/sim/sim.json`의 `tile_size_m`에서 읽는다(아직 sim 로더가 없으므로 view 에서 `FileAccess`로 직접 읽되 "SE-001 병합 후 교체" 주석). 바닥 평면 + 타일 선. `world_to_tile`, `tile_to_world`, `is_inside`.
  - `project/view/grid/tile_cursor.gd` — `TileCursor`. 화면 좌표 → y=0 평면 레이캐스트 → 타일 강조 메시 + 좌표 라벨.
  - `project/view/input/input_actions.gd` — 런타임에 `InputMap.add_action` 으로 `camera_rotate_cw/ccw`, `camera_zoom_in/out`, `camera_pan_left/right/up/down`, `camera_pan_drag` 등록(기본 키: Q/E, 휠, WASD, 휠 클릭 드래그). `project.godot`의 `[input]`은 render-engineer 쓰기 범위 밖이라 사람 결정 전까지 이 방식.
  - `project/view/scenes/grid_sandbox.tscn` — 실행용 샌드박스(카메라 + 그리드 + 커서 + 디버그 라벨).
  - `project/tests/view/test_iso_camera.gd`, `test_grid_view.gd`, `test_tile_cursor.gd`, `test_input_actions.gd`, `test_view_boundary.gd`.
  - `project/tests/view/screenshots/SE-002/grid_yaw45_zoom2.png` — 사람 검수용 스크린샷(1920×1080).

## 수용 기준

- [ ] AC1. `IsoCamera`의 `Camera3D.projection == PROJECTION_ORTHOGONAL`이고 초기 회전이 피치 −30° ±0.5°, 요 45° ±0.5°다(값은 `iso_camera_params.tres`에서 읽음). → `test_iso_camera.gd::test_orthographic_and_fixed_angles`
- [ ] AC2. `rotate_cw()`마다 요가 정확히 +90°, `rotate_ccw()`는 −90°. `rotate_cw()` 4회 후 요가 다시 45°(mod 360)이고, 중간값은 `{45, 135, 225, 315}`만 나온다. 피치는 회전 중 불변. → `test_iso_camera.gd::test_rotate_90_degree_steps_only`
- [ ] AC3. 줌은 `iso_camera_params.tres`의 4개 `size` 값(엄격히 증가)만 쓴다. 최대 단계에서 `zoom_out()`, 최소 단계에서 `zoom_in()`은 값 불변. 단계 수가 4가 아니면 `push_error`. → `test_iso_camera.gd::test_zoom_four_levels_clamped`
- [ ] AC4. `pan(Vector2)`은 피벗을 지면(XZ)에서만 옮기고(y 불변), 피벗은 `[−margin, grid_size + margin]` 안으로 클램프된다: `pan(Vector2(1e6, 1e6))` 후 피벗 x, z ≤ `grid_size + margin`. → `test_iso_camera.gd::test_pan_clamped_to_grid`
- [ ] AC5. `GridView`는 tiers.json 의 `tier_1.grid_size`(24)와 sim.json 의 `tile_size_m`(1.0)으로 초기화되고, `project/view/**/*.gd`에 `24` 리터럴이 없다. `world_to_tile(Vector3(3.4, 0, 7.9)) == Vector2i(3, 7)`, `tile_to_world(Vector2i(3, 7)) == Vector3(3.5, 0, 7.5)`(타일 중심), 그리드 밖 좌표는 `is_inside == false`. → `test_grid_view.gd::test_size_from_data_tables`, `::test_world_tile_roundtrip`, `::test_outside_is_not_inside`
- [ ] AC6. 타일 판정이 모든 카메라 상태에서 맞는다: 4방향 회전 × 4줌 = 16조합 각각에서 타일 (5,5)와 (0,23)의 중심을 `camera.unproject_position`으로 화면에 투영한 뒤 `TileCursor.screen_to_tile`로 되돌리면 같은 타일이 나온다. → `test_tile_cursor.gd::test_screen_to_tile_all_rotations_and_zooms`
- [ ] AC7. 호버 중 커서 메시의 위치가 해당 타일 중심(y=0 + 작은 오프셋)이고, 그리드 밖에서는 커서가 숨겨진다(`visible == false`). → `test_tile_cursor.gd::test_cursor_follows_tile_and_hides_outside`
- [ ] AC8. `InputActions.register()` 후 `InputMap.has_action()`이 위 액션 전부에 대해 `true`. `project/view/**/*.gd`에서 `KEY_`, `MOUSE_BUTTON_` 리터럴은 `input_actions.gd`에만 있다. → `test_input_actions.gd::test_actions_registered`, `test_view_boundary.gd::test_no_raw_key_checks_outside_input_actions`
- [ ] AC9. `project/view/**/*.gd`에 `project/sim/`, `project/core/`를 수정하는 코드가 없고(`load("res://sim/`, `load("res://core/` 0건 — 현재 비어 있으므로 0이어야 함), `project/data/`에 쓰는 `FileAccess.WRITE` 0건. → `test_view_boundary.gd::test_view_does_not_touch_sim_or_data`
- [ ] AC10. 샌드박스 수동 실행 시 아래 "수동" 절의 기대 화면이 나오고 스크린샷 `project/tests/view/screenshots/SE-002/grid_yaw45_zoom2.png`가 1920×1080 으로 커밋된다. → qa 수동 확인 + `test_view_boundary.gd::test_screenshot_exists_1080p`(파일 존재·크기만)
- [ ] AC11. `tools/run_tests.sh project/tests/view` 전체 녹색. → qa 리포트 실행 로그

### 남은 질문 / 메모 (producer)

1. **동시 작업 메모:** 작업 중 `project/data/sim/sim.json`, `project/data/schemas/sim.schema.json` 이 다른 에이전트(SE-006 으로 추정)에 의해 바뀌어 있었다. render-engineer 는 손대지 않았고, `tile_size_m` 은 그대로 1.0 이라 이 티켓에 영향 없다. 커밋 시 SE-002 변경과 섞이지 않게 분리할 것.
2. **스크린샷 이름의 `zoom2`:** 0부터 센 인덱스 2(size 20 m, 티어 1 부지 전체가 보이는 단계)로 해석했다. 1부터 센 "2단계"가 의도였다면 기본 줌 인덱스 또는 파일 이름을 바꿔야 한다.
3. **줌 size 값**(`7, 12, 20, 32` m)은 티어 1 기준 시안이다. 티어 6(400×400)까지 같은 4단계로 커버하려면 티어별 size 세트(또는 그리드 크기 비례)가 필요하다 → 청크 로드 티켓에서 결정. 아트 디렉터가 `iso_camera_params.tres` 에서 조정 가능.
4. **Git LFS:** `*.png` 가 LFS 대상이다. 스크린샷 커밋 전 `git lfs install` 확인 필요(status 의 사람 결정 항목).
5. **스크린샷 자동 비교:** 이 환경에서는 Xvfb + llvmpipe(opengl3)로 실제 렌더 캡처가 됐다. CI 에 같은 러너를 두면 골든 비교 자동화(status 선택지 b)가 가능하다는 근거. 별도 티켓 제안.
6. 게임패드 "커서 모드"(스틱으로 화면 커서 이동)는 범위 밖이라 미구현. 기본 바인딩만 넣었다.
