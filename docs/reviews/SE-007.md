## 확인한 것

- **포화 로직 ↔ tick.md:161 S4 문장 일치.** 스펙: `k = s0 × ticks_per_second`, `sat_s = ⌈max_ticks_per_step ÷ k⌉`, `delta_s > sat_s` 이면 `delta_s = sat_s + (delta_s mod 1)`, 그 뒤 `us = max(0, roundi(delta_s × 1,000,000))`, `acc += us × k`. 코드 `tick.gd:101` `k = s0 * config.ticks_per_second`, `:105` `sat_s = (config.max_ticks_per_step + k - 1) / k`(정수 올림 나눗셈 = ⌈·⌉, `k ≥ 1` 보장: `s0 ≠ 0` 은 `:96` S3 에서 걸러지고 `ticks_per_second > 0` 은 `sim_config.gd:42-44`), `:106-107` `if d > sat_s: d = sat_s + fposmod(d, 1.0)`, `:108` `us = maxi(0, roundi(d * US_PER_S))`, `:109` `_acc += us * k`. 식 하나하나 대응.
- **오버플로가 실제로 막히는가.** 현재 데이터(`tps` 10, 상한 30)에서 `sat_s` = 3/2/1(배속 1/2/3). 포화 후 `d < sat_s + 1 ≤ 4` 이므로 `us < 4×10^6`, `us × k ≤ 4×10^6 × 30 = 1.2×10^8`, `_acc` 는 `10^6 + 1.2×10^8` 미만 — int64 는 물론 int32 범위에도 든다. `roundi()` 입력도 `< 4×10^6`. `d = 1e300` 은 `fposmod(1e300, 1.0) = 0` 으로 `d = sat_s` 가 되어 정확히 상한 틱(테스트 `test_replay_qa.gd:181,186` 에서 확인됨). 음수·NaN·INF 는 `:100` 과 `:108` 의 `maxi(0, …)` 가 기존대로 0 틱(`test_step_extreme_delta` 녹색).
- **S5 `budget` 과 잔여가 포화 전 계산과 같은가.** `sat_s × k ≥ max_ticks_per_step` 이므로 포화된 `q ≥ max_ticks_per_step` → `budget = max_ticks_per_step`(자르지 않은 경우와 동일). 잔여 `acc mod 10^6` 은 `us mod 10^6` 에만 의존하고(`k × 10^6 ≡ 0`), 정수 초를 잘라도 `us mod 10^6` 은 소수부에서만 나오므로 같다. `test_tick.gd:318-324 test_step_saturation_keeps_fraction` 이 `step(10.05)` → 30, `step(0.04)` → 0, `step(0.01)` → 1 로 잔여 0.5틱분 보존을 단언(단순 포화 `us = min(us, cap)` 이었다면 잔여 0 → `step(0.01)` 0틱으로 실패).
