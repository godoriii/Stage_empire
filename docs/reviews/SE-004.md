| 7 | `project/ui/hud/debug_hud.gd` 수정(티켓 "포함" 목록에 파일명 없음) | **수용** | 티켓 본문 "DebugHud 에 현재 시안 한 줄" 의 구현이고 `ui/` 는 render-engineer 범위. 빈 값이면 줄을 숨겨 SE-002 화면 불변(qa 픽셀 차 0) |

### 추가 판단: `outline.gdshader:22` `abs(PROJECTION_MATRIX[1][1])`

타당하다. 직교 투영에서 `[1][1]` 의 크기는 렌더러와 무관하게 `2 / size` 이고, 부호만 렌더 타깃 Y 뒤집기 보정(Compatibility 의 오프스크린 타깃, forward_plus 의 Vulkan NDC 보정)에 따라 바뀐다. `abs()` 는 두 경우 모두에서 같은 m/px 를 주고, `VIEWPORT_SIZE.y` 는 항상 양수다. 원근 분기(`[3][3] < 0.5`)는 직교에서 1, 원근에서 0 이라 올바르다. `skip_vertex_transform` 로 뷰 공간 `VERTEX`·`NORMAL` 을 직접 쓰는 것도 Godot 4 규약대로다. Vulkan 실행은 이 환경에서 못 해 봤으므로(qa "검증 불가") AC13 사람 캡처가 첫 검증이며, 외곽선이 안 보이면 이 줄이 첫 의심점이라는 qa 절차 5 에 동의한다.

## 발견 사항 (반려 사유 없음)

반려 수준 없음. 아래는 낮음·참고.

- **낮음** `project/view/shaders/shader_variants.gd:38-39` — `load_material()` 이 `.tres` 로드 실패(파일 손상·경로 변경) 시 조용히 `null` 을 돌려주고, `apply()` 는 그 `null` 을 `material_override` 에 써서 "시안 적용" 이 default 와 구별되지 않는다. 유효 id 인데 `null` 이면 `push_error` 로 구분하라. 지금은 `.tres` 6개가 테스트로 로드 확인되므로 즉시 문제는 아님(후속 티켓 B 에 포함).
- **낮음** `project/tests/view/screenshots/SE-004/` — 플레이스홀더 세트의 **default 캡처가 없다**(a/b/c 만). 아트 디렉터가 "시안 → 기존 룩" 차이를 같은 장면에서 보려면 `default_yaw45_zoom2.png` 가 있어야 한다. 티켓 AC12 는 4장만 요구하므로 통과이지만, 사람 캡처 단계(티켓 블록 (3))에 `for m in default a b c` 로 한 장 더 찍도록 producer 가 status 의 사람 작업 명령을 고치면 비용 0 이다.
- **참고** `project/tests/view/test_se004_outline_qa.gd:11-16` — 행·열 범위가 픽셀 좌표 리터럴이라 `shader_placeholders.tres`·카메라 파라미터·HUD 가 바뀌면 깨진다. 스크린샷 자체가 커밋 산출물이고 바뀌면 재캡처가 전제이므로 수용. 깨질 때 메시지가 어긋난 행을 보여 주므로 진단은 가능.
- **참고** `toon.gdshader:19-30` uniform 기본값이 `.tres` 값과 다르다(예: `shadow_tint` 기본 `(0.3,0.3,0.4,1.0)` vs `.tres` `(0.32,0.3,0.45,0.55)`). 주석 "아래 기본값은 쓰지 않는다" 와 테스트(모든 uniform `.tres` 명시)로 안전하지만, 코드에서 `ShaderMaterial.new()` 로 만드는 길이 생기면 기본값이 살아난다 — AC3 테스트가 `ShaderMaterial.new()` 0건을 고정하므로 현재는 문제 없음.
- **참고** qa 가 지적한 "셰이더 컴파일이 헤드리스 GUT 에서 검증되지 않는다" 는 맞다. 현재 컴파일 검증은 Xvfb 캡처(gl_compatibility)뿐이고 CI 에 그 단계가 없다. CI 는 이미 `lfs: true`(`.github/workflows`)라 스크린샷 로드 테스트는 CI 에서 돈다 — qa 리포트의 LFS 우려는 해당 없음. → 후속 티켓 C.

## 반려 시 새 티켓 제안

반려 아님. 승인 후 producer 가 발행할 후속 티켓 후보(우선순위 순):

- **A. 머티리얼 슬롯 규약 확정(accent 마스크 채널) + style-guide 갱신** — game-designer/art-pipeline, 아트 디렉터 결정과 함께. 수용 기준: `docs/style-guide.md` "머티리얼 슬롯 이름" 행이 "초안" → "확정" 으로 바뀌고 accent 영역 표기 방식(정점 알파 0 / 별도 서피스 / UV2 중 하나)과 `glass` 슬롯과의 관계가 한 문단으로 적힌다; `toon.gdshader` 의 accent 구현이 그 규약과 일치하거나 변경 티켓이 발행된다; `tools/assets/` glTF 임포터 스펙에 같은 규약이 들어간다.
- **B. 시안 확정 후 기본 머티리얼 적용(default 교체)** — render-engineer, AC13·시안 선택 뒤. 수용 기준: 선택된 시안의 `.tres` 가 샌드박스·스파이크의 기본 머티리얼이 되고 `--material=` 없이도 적용된다; `ShaderVariants.load_material()` 이 유효 id 로드 실패 시 `push_error` 한다(테스트 1건); SE-002 스크린샷은 룩 변경 ADR/결정 로그와 함께 교체된다; `results/SE-004.md` 의 실측 표가 채워진 상태를 전제로 한다.
- **C. CI 에 Xvfb 셰이더 컴파일·캡처 비교 단계** — qa/producer. 수용 기준: CI 가 `xvfb-run … --rendering-driver opengl3` 로 `grid_sandbox.tscn -- --material=b --se-screenshot=` 을 한 번 실행해 종료 코드 0 과 1920×1080 PNG 생성을 확인한다; 셰이더 컴파일 오류가 콘솔에 있으면 CI 가 실패한다; 커밋된 `SE-004/*.png` 와의 픽셀 비교는 선택(결정적 환경에서만 켠다).
- **D. 스크린스페이스 외곽선(박스 모서리 틈·바닥 접점 해결)** — render-engineer, 시안 선택 후 룩 티켓. 수용 기준: `b_yaw45_zoom0.png` 재캡처에서 바 카운터 수직 모서리(y 510~639)의 어두운 연속 픽셀 폭이 시안 설정값(2 px)과 같다; 캡슐 외곽선 폭은 SE-004 qa 테스트 그대로 통과한다; 구성 E primitives 가 default 의 ≈ 2.0 배보다 줄거나 같다(역면 헐 패스 제거 시).
- **(producer 메모, 티켓 불필요)** 티켓 AC8 의 "TileCursor 메시 `material_override == null`" 문구를 "적용 전 값 그대로" 로 정정. 사람 캡처 명령에 `default` 한 장 추가. 시안 선택 질문에 두 줄 덧붙임: "림은 역광(무대 스포트)에서만 보이는 설계", "박스 오브젝트 외곽선은 설정보다 가늘 수 있음(후속 D)".
