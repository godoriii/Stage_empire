## 발견 사항

1. **(낮음) `_process` → `step` 실시간 경로를 자동으로 도는 테스트가 없다.**
   - 위치: `test_main_scene.gd:31`, `test_se040_integration_qa.gd:25`가 `drive_realtime = false`로 둔다.
   - 왜 문제인가: 통합 테스트는 `session.advance`로 진행하고, CI 캡처도 `driver.drive(고정 델타)`를 쓴다. 그래서 `SimDriver._process`, 시작 메뉴 `hold` 해제(`main.gd:215`), `driver.set_process`(`main.gd:108`)가 함께 도는 경로는 소스 검사(AC1)와 qa의 수동 Xvfb 실행(AC7)으로만 덮인다.
   - 이런 회귀가 CI를 통과한다: `hold`가 안 풀려 시간이 멈추는 경우, `set_process`가 빠지는 경우, priority가 역전되는 경우.
   - 지금은 코드가 짧고 소스 검사가 있어 위험이 작다. SE-043 사람 플레이 전에 막는 것이 싸다.
   - 고칠 방법: `drive_realtime = true`로 씬을 띄우고 프레임을 await해 다음 4가지를 단언하는 테스트 1건을 둔다.
     - 메뉴가 떠 있는 동안 `loop.tick` 불변
     - 메뉴를 닫은 뒤 증가
     - 배속 0이면 불변
     - `SimDriver.last_ticks`의 합 = tick 증가량
   - 아래 후속 1로 둔다.
2. **(낮음) 자동 플레이 배속이 sim.json 값과 같은 리터럴이다.**
   - 위치: `main.gd:42` `AUTOPLAY_SPEED: int = 3`.
   - 왜 문제인가: 낮 구간 최대 배속은 sim.json `phases[].speeds`에 있다(HUD 배속 버튼도 거기서 만든다). 이 값이 바뀌면 sim이 `time.speed_requested {3}`을 거절한다. 그러면 자동 플레이 일수, 캡처 2장, AC2 테스트가 데이터 변경에 이유 없이 끌려간다(원칙 3).
   - 고칠 방법: `UiData`·`CrowdData`가 이미 읽는 sim.json에서 `phases[0].speeds`의 최댓값을 쓴다.
3. **(낮음) 경계 테스트의 session 멤버 허용 목록이 첫 단계만 검사한다.**
   - 위치: `test_view_boundary.gd:557`. `session.artist.<무엇이든>`이 통과한다.
   - 현재 사용은 `main.gd:269 session.artist.config.artist_ids()`(읽기) 하나라 위반은 없다. 그러나 `session.artist.book(...)`을 넣어도 테스트가 실패하지 않는다.
   - `session.new_game(`도 호출 수를 세지 않는다. 지금은 `_create_session` 1곳뿐이다.
   - 고칠 방법:
     - `session.artist.` 다음 멤버를 `config` 하나로 제한한다.
     - `session.new_game(` 호출 1건을 단언한다.

   - 게임 규칙이 아니라 캡처 도구 타이밍이다. CLAUDE.md 원칙 3이 열거한 범주(가구·아티스트·장르·이벤트·티어·밸런스)에 들지 않으므로 반려 근거는 아니다.
   - 다만 view는 표시 상수를 `.tres`에 두는 관례를 따른다(`crowd_view_params.tres preset_light_offset_cells`). 그래서 SE-054(UI 표시 상수 정리)에 함께 넣으면 일관된다.
5. **(참고) 부팅 때 `new_game`이 두 번 실행된다.**
   - 위치: `main.gd:135`(팩토리)와 `main.gd:95`(SN5 경로).
   - 같은 시드라 결과는 같다(SN5 "같은 seed → 같은 1일차 해시"). 의도된 설계이고 결과 절에도 적혀 있다. 비용이 문제가 되면 팩토리 쪽을 세계 생성 없는 생성자로 바꾸는 것은 sim 티켓 몫이다.
6. **(참고) `StageLights.bind`의 반환값을 버린다.**
   - 위치: `main.gd:174`. `bind`는 `bool`을 돌려준다.
   - AC-38e는 "실패 반환 **또는** 폴백 색"이고, 폴백 색이 들어가 있으므로 충족이다. 설정 오류는 `push_error`로 보이고 AC7 grep에 걸린다.
7. **(참고) 음수 시드의 계약이 서로 다르다. 기존 문제이고 이 티켓 밖이다.**
   - `test_seed_resolution_ac39c:130`은 `--se-seed=-7`을 "음수 허용"으로 통과시킨다. events.md:69도 `int` 전체를 허용한다.
   - 그런데 `rng.gd:22-24`는 음수 시드에 `push_error`를 내고 접는다.
   - 사용자가 음수 시드를 넣으면 AC7류 로그 grep에 오류 1줄이 생긴다. game-designer가 events.md와 rng.gd 중 어느 쪽에 맞출지 정하면 된다.
8. **(참고) 시작 시각 시드에 `Time.*`를 쓴다.**
   - 위치: `main.gd:120` `Time.get_unix_time_from_system()`.
   - 결정성 검사 항목에 걸리는 패턴이지만 AC-39c가 요구한 것이다("sim 밖, 시작 시각에서 1회"). 값은 `session.new_game_requested {seed}`로 sim에 들어가고, RNG는 `core/rng.gd`만 쓴다.
   - 테스트와 캡처는 모두 `--se-seed`로 고정한다. 위반이 아니다.
   - `SEED_MASK`(`main.gd:46`)는 `SeededRng.MASTER_SEED_MAX`와 같은 값의 사본이다. view가 `SeededRng`를 참조하면 AC1 허용 목록을 넓혀야 하므로 사본이 맞다.
