## 판단 요청 4건

### 1. 배속 2~3 보간 끊김(qa 발견 1) — 이 PR 에서 고치지 않는다. SE-040 AC 로 넘긴다. 방식은 `time.speed_changed` 구독.

- **넘기는 이유.** 구현은 view 계약 문구 `t = acc ÷ tick_len`(`audience.md:340`)과 티켓 범위 문구(`SE-038.md` "범위" 절)를 그대로 따랐고, AC1 은 1배속 기준이다. 배속이 1 이 아닌 틱 도착은 `SimDriver`(SE-040)가 들어와야 생기므로 이 브랜치에서는 재현 경로가 없다(샌드박스는 1틱 합성). 계약 문구를 바꾸는 일은 `docs/gdd/` 소유(game-designer)라 이 PR 에서 고치면 범위 밖 변경이 된다(검사 6). 그래서 SE-040 통합 AC + game-designer 계약 1줄 개정으로 넘긴다.
- **`time.speed_changed` 가 원칙 1·2 에 맞는 쪽이다.**
  - 원칙 1(렌더는 구독만): 두 방법 모두 구독만 하므로 차이 없다.
  - 원칙 2(시간은 `core/` 틱 루프만 진행, `_process` 는 표시만): 배속은 sim 이 결정하는 값이고(SE-040 "배속은 sim 이 결정") `time.speed_changed {speed}` 가 그 결정의 공식 출력이다(events.md:21). 도착 간격 측정은 view 가 프레임 델타로 "지금 시간이 얼마나 빨리 가는가"를 추정하는 두 번째 시계다. 그 추정값은 프레임 양자화로 흔들리고(60 fps·30 tick/s 에서 1~2 프레임, 프레임 하나에 틱 여러 개가 오면 간격 0), 배속이 바뀐 직후 한 틱 늦고, 일시정지(`speed 0`) 판단도 할 수 없다. 결정적이지 않은 추정을 표시 계약에 넣을 이유가 없다.
  - 구현 메모(SE-040 인계): `t = clamp(acc × speed ÷ tick_len, 0, 1)`(= `tick_len ÷ speed`). `speed 0` 이면 `t` 를 진행하지 않는다(나눗셈 없음). `time.speed_changed` 는 값이 바뀔 때만 오므로 초기값이 필요하다 — 새 게임은 sim 기본 배속, 로드는 `session.loaded` 페이로드(아래 2번과 같은 확장)에서 받는다.

### 2. 공연 중 로드 시 스포트 복구 — 둘 다 그대로는 틀리다. `session.loaded` 페이로드에 공연 상태를 싣고 view 가 그것을 구독하는 쪽이 맞다.

- **`show.started` 재발행(안 A) 반대.** `show.started` 는 "공연 첫 틱, 하루 0~1회"라는 도메인 사실이다(SE-030 브랜치 events.md:43). sim 구독자가 있다: reputation 이 `show.started` 를 받아 `show_day`·`show_genre` 를 상태에 쓴다(SE-030 브랜치 `reputation.md:40`, 스냅샷 대상 `:46`). 지금은 같은 값을 덮어써 무해하지만, "로드 재발행이 sim 상태를 건드리지 않는다"를 구독자마다 보장해야 하고 하루 1회 계약을 깬다. 앞으로 공연 수를 세는 구독자(통계·위기)가 붙으면 바로 이중 집계가 된다.
- **view 가 `time.phase_changed` 를 구독(안 B)만으로는 안 된다.** 공연 중 로드면 다음 `time.phase_changed` 는 show→close 라 켜는 신호가 오지 않는다. 그 이벤트를 로드 때 재발행하는 것은 안 A 보다 위험하다 — economy(`to:"close"` 정산)·build(`to:"evening"` sync)·artist(`to:"evening"` 라인업) 가 반응한다(events.md:19,25,35,51). 또 단계가 `show` 여도 공연이 없는 날(`show.skipped`, ST1·ST2)이 있으므로 단계만으로는 스포트를 켤지 정할 수 없다.

1. **AC 추가(배속 보간).** `CrowdView` 가 `time.speed_changed` 를 구독해 `t = clamp(acc × speed ÷ tick_len, 0, 1)`, `speed 0` 이면 정지. 테스트: 배속 3 으로 연속 `agent_moved`(틱당 +1 타일)를 `tick_len ÷ 3` 간격 프레임으로 주입 → 프레임당 이동량이 균일(최대·최소 차 ≤ 1e-3 m)하고 표시 속도 = 실제 속도. 선행: game-designer 가 `audience.md:340` 문구를 `t = acc × speed ÷ tick_len` 으로 1줄 개정.
2. **AC3 e2e 에 "공연 중 저장 → 로드" 케이스 1건.** 로드 직후(다음 틱 전) 스포트 수 == 저장 시점 수. 아래 새 티켓 B 가 먼저 병합돼야 녹색이 된다(아니면 기대 실패로 표시하고 B 를 의존으로 건다).
