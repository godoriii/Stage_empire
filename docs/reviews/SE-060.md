## 확인한 것 (항목별)

### AC1 — `undo_created_dirs` 분할(`mutate_and_test.sh:109`)

`readarray -d / -t parts < <(printf '%s' "$rest")` 를 입력 종류별로 따라갔다.

- **입력의 출처.** `rest` 는 `REST_PRE` 에서 맨 앞 `/` 하나를 뗀 값이다(:103). 비어 있으면 아무것도 지우지 않는다(:104). `REST_PRE` 는 `resolve_no_create` 루프(:77-80)가 `"/$(basename "$p")"` 를 앞에 붙여 만든다.
- **빈 성분.** `basename` 은 빈 문자열을 내지 않는다. 그리고 `dirname` 이 연속 `/` 를 접는다. 그래서 `REST_PRE` 에 `//` 가 생기지 않는다.
  - 가정상 `a//b` 가 들어와도 `readarray -d /` 는 `(a, "", b)` 로 나눈다. 이전 `IFS=/ read -r -a` 와 같다.
  - 빈 성분에서는 `d="${d%/}/"`(:110)가 바로 앞 경로를 다시 넣을 뿐이다. 중복 `rmdir` 은 실패하고 무시된다.
- **끝 슬래시.** `readarray -d /` 는 구분자를 줄 끝으로 다룬다. 그래서 `a/` 는 `(a)` 가 된다. `read -a` 와 같고, 빈 꼬리 성분이 생기지 않는다.
- **마지막 성분.** `printf '%s'` 는 끝 개행을 붙이지 않는다. 그래서 구분자 없는 마지막 조각이 그대로 마지막 원소가 된다. `-t` 는 구분자(`/`)만 떼고 개행은 건드리지 않는다.
- **성분 안의 개행.** 입력이 `$'g1x\nfoo/y'` 이면 `(g1x⏎foo, y)` 로 나뉜다. 정리 목록은 `EXIST_PRE/g1x⏎foo/y`, `EXIST_PRE/g1x⏎foo` 다. 이미 있던 `g1x` 는 목록에 없다. 이전 `read` 는 `(g1x)` 로 잘렸다(SE-048 [낮음] 1).
- **glob 문자.** `readarray` 는 확장을 하지 않는다. `"${parts[@]}"`·`"${list[$i]}"` 는 모두 따옴표 안이다. `d=` 대입은 glob 하지 않는다. 그래서 `g*x`·`[g]1x` 성분은 글자 그대로 남는다.
- **정리 범위.** 목록은 여전히 `EXIST_PRE` 아래의 `REST_PRE` 성분뿐이다. 깊은 쪽부터 `rmdir`(비어 있을 때만) 한다(:111). `EXIST_PRE` 자신은 목록에 들어가지 않는다(첫 원소가 `EXIST_PRE/<성분1>`).
- **판정 순서.** 경로 판정(:70-98)과 사후 검사(:113-124)는 diff 밖이다. 삭제 경로 `safe_remove_work`(:129-139)와 `rm -rf` 조건(`"$BASE"/se_mutate.?*`)도 diff 밖이다. diff hunk 는 `@@ -102,9 +102,11 @@` 하나뿐이다.
- **실패 시 방향.** `readarray` 가 없는 bash(3.2)이거나 `/dev/fd` 가 없으면 `parts` 가 빈 채로 남는다. 그 경우 `rmdir` 은 하나도 일어나지 않는다. 만든 디렉터리가 남을 뿐이고 기존 디렉터리는 지우지 않는다(안전한 쪽).
- **환경.** `set -u` 아래 `"${parts[@]}"` 도 문제없다. `rest` 가 비어 있지 않으면 원소가 1개 이상이기 때문이다.
- **bash 버전.** `readarray -d` 는 bash 4.4+ 가 필요하다.
  - CI(`.github/workflows/ci.yml`)는 이 스크립트를 실행하지 않는다(`mutate_and_test` 참조 0건). 러너도 전부 `ubuntu-latest` 라 bash 5.x 다.
  - `tools/bot/README.md` 에는 bash 버전 언급이 없다(참고 1).
- qa 의 세 구현 비교 표(`[g]1x/a` 행 추가로 glob 회귀도 잡힘을 보인 것)는 위 추적과 맞는다. 하니스가 구현마다 다른 결과를 낸다는 점에서 감도도 있다.
