# ADR-0001 엔진은 Godot 4.x

- 날짜: 2026-10-09
- 상태: 결정 (조건부: 프리프로덕션 성능 스파이크 통과)
- 2026-10-09 1차 측정(SE-003, Mac mini M1 내장 GPU): 구성 B(5,000 + 라이트 32 + 셰도우 8) 21.7fps 로 60fps 미달. 원인은 셰도우 라이트마다 군중 전체 재렌더(단일 병목). 프로덕트 오너 결정으로 군중 그림자를 끄고(SE-013) 재측정한다. 재측정 기준 기기: 60fps 는 dGPU(Vulkan) PC, 30fps 는 M1/Iris Xe 급. 재측정도 실패하면 이 ADR 을 대체하는 Unity 재검토 ADR 을 쓴다. 기한: 프리프로덕션 4주 안(PRD).
- 출처: docs/PRD.md "기술 요구사항", "결정이 필요한 질문"

## 결정

Godot 4.x, GDScript 기본 + 필요한 곳만 C#. 프리프로덕션 4주 안에 "인스턴싱 캐릭터 5,000 + 동적 라이트 32개에서 60fps" 스파이크를 돌리고, 실패할 때만 Unity(URP 3D)를 재검토한다.

## 이유

- 씬·리소스가 텍스트 파일이라 에이전트가 읽고 쓰기 쉽고 diff 리뷰가 된다.
- 로열티 없음, 가벼운 빌드, 로우폴리 3D에 충분.
- 약점(대규모 인스턴싱·셰도우 성능, 콘솔 직접 포팅 불가)은 스파이크와 포팅 파트너로 다룬다.

## 결과

- 스파이크 티켓이 프리프로덕션의 첫 render-engineer 티켓이 된다.
- 스파이크 실패 시 이 ADR을 대체하는 ADR-000N을 쓰고, 그 전까지 엔진 의존 코드는 `project/view/`에 가둔다.
