## 결정

Godot 4.x, GDScript 기본 + 필요한 곳만 C#. 프리프로덕션 4주 안에 "인스턴싱 캐릭터 5,000 + 동적 라이트 32개에서 60fps" 스파이크를 돌리고, 실패할 때만 Unity(URP 3D)를 재검토한다.

## 이유

- 씬·리소스가 텍스트 파일이라 에이전트가 읽고 쓰기 쉽고 diff 리뷰가 된다.
- 로열티 없음, 가벼운 빌드, 로우폴리 3D에 충분.
- 약점(대규모 인스턴싱·셰도우 성능, 콘솔 직접 포팅 불가)은 스파이크와 포팅 파트너로 다룬다.

## 결과

- 스파이크 티켓이 프리프로덕션의 첫 render-engineer 티켓이 된다. (이력: SE-003 → 관문 실패 → SE-013 구성 E → 2026-10-09 통과)
- 스파이크 실패 시 이 ADR을 대체하는 ADR-000N을 쓰고, 그 전까지 엔진 의존 코드는 `project/view/`에 가둔다. (이력: 재측정 통과로 대체 ADR 은 쓰지 않는다. 엔진 의존 코드를 `project/view/`에 가두는 원칙은 ADR-0002 로 계속 유지)
- 재측정 통과의 전제 조건은 "관객 군중은 그림자를 드리우지 않는다"(docs/style-guide.md, 2026-10-09 프로덕트 오너 결정)이다. 군중 그림자를 다시 켜려면 이 ADR 의 측정을 다시 해야 한다(B 21.75 fps).
- 이후 성능 관문은 티어별 마일스톤 관문(PRD)에서 다룬다. 기본 룩은 시안 B(셀 3단계 + 외곽선 2px + 림)이며 그 비용(E 에서 −18 fps, primitives ×2.0)은 위 수치에 포함돼 있다(SE-018 에서 default 로 적용).
