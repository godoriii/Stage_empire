# Stage Empire v2 — 컨셉 초안 (페스티벌 준비 → 개최 → 결과 → 다음 페스티벌)

- 상태: **초안, 프로덕트 오너 검토 대기** (2026-10-20)
- 근거: 프로덕트 오너 피드백 2026-10-20 — "건설→공연 루틴이 맞물리지 않는다, 너무 많은 것을 넣었다, 단순화하고 페스티벌 준비 루프로 전면 개편"
- v0(클럽 운영 시뮬)은 지우지 않는다. `main`의 마지막 상태를 태그 `v0-club-sim`으로 보존하고, SE-062·SE-065 브랜치는 병합하지 않은 채 보관한다.

## 1. v0에서 무엇이 안 맞았나

| 증상 (플레이·봇 통계) | 원인 |
|---|---|
| 건설과 공연이 따로 논다 | 건설은 아무 때나, 공연은 매일 반복. 내가 지은 것이 공연 결과에 **얼마나·왜** 영향을 줬는지 화면에 안 보인다(커버리지 bp, 만족 보너스 상한 같은 숨은 수치). |
| 매일이 비슷하다 (SE-042: 정책마다 등급 1칸) | 같은 클럽에서 같은 크기의 공연을 매일 반복. "한 번의 큰 승부"가 없다. |
| 처음 10분에 이해해야 할 게 너무 많다 | 티어 1부터 건설·아티스트·공연·관객·경제·명성 6개 시스템 + 일일 정산·임대료·구제. |
| 결과가 납득되지 않는다 | 만족도 = 여러 곱·차의 합성. 실패 이유를 한 줄로 말할 수 없다. |

**교훈**: 시스템 수가 아니라 **"내 결정 → 눈에 보이는 결과 → 이유"의 연결**이 재미를 만든다.

## 2. 게임의 핵심 (한 문장)

> **한 번의 페스티벌을 설계해 걸고, 그날의 결과를 눈으로 보고, 이유를 배워 다음 페스티벌을 더 크게 연다.**

- 판타지: 동네 공원 1,000명 페스티벌에서 시작해 5만 명 메가 페스티벌의 주최자가 된다.
- 재미의 원천 세 가지
  1. **준비의 손맛** — 한정된 예산으로 라인업·시설·인력을 맞추는 퍼즐.
  2. **개최의 긴장과 보상** — 내 계획대로 사람이 몰리고, 헤드라이너 순간에 터진다(또는 화장실 줄이 터진다).
  3. **납득되는 성적표** — "화장실 대기 30분 → 만족도 −8". 다음에 무엇을 바꿀지 바로 안다.
- 레퍼런스: Game Dev Tycoon(기획→출시→리뷰→다음 작품의 명쾌한 사이클), Football Manager 경기일(준비→관람→결과), Two Point 시리즈(배치·톤).

## 3. 핵심 루프 (페스티벌 1회 = 15~25분)

| 단계 | 플레이어가 하는 일 | 시간 | 화면 |
|---|---|---|---|
| ① 제안 | 다음 페스티벌 기회 2~3개 중 하나 선택: 장소(부지 크기), 시즌, 예상 규모, 스폰서 조건 | 1분 | 카드 선택 |
| ② 준비 | 4가지를 정한다. 시계가 멈춰 있다 | 10~15분 | 부지 맵 + 패널 |
| ③ 개최 | 하루가 자동으로 흘러간다(배속). 돌발 카드 2~3장에 선택으로 대응 | 2~4분 | 부지 맵 + 군중 |
| ④ 결과 | 성공/실패 등급, 숫자 3개, 원인 리뷰 3~5줄, 해금 | 1~2분 | 성적표 |
| ⑤ 다음으로 | 돈·명성·해금이 이어진다 → ①로 | — | — |

**② 준비의 4가지 (각 3~5개 손잡이)**

| 기둥 | 결정 | 결과에 미치는 영향(눈에 보여야 함) |
|---|---|---|
| 라인업 | 무대 슬롯에 아티스트 배치(출연료·집객력·장르), 헤드라이너 1명 | 관객 수, 기대치 |
| 시설 | 부지에 무대·바/푸드·화장실·의료·입구 배치(시설 8종 내외) | 대기 시간, 이동 거리, 매출 |
| 인력 | 보안·바·청소 인원을 구역에 배정 | 대기열 속도, 사고·쓰레기 |
| 티켓·홍보 | 티켓 가격, 홍보 예산 | 관객 수 vs 1인당 수익 |

준비 화면에는 항상 **예상치 미리보기**(예상 관객, 화장실 1개당 인원, 예산 잔액, 위험 경고 "화장실 부족")가 떠 있다. 개최 전에 이미 "왜"를 볼 수 있어야 한다.

**④ 결과의 규칙**: 점수는 많아야 3개(관객 수·만족도·수지). 만족도 감점은 원인별로 쪼개서 보여준다. 모든 감점 원인은 ②의 결정 하나로 되돌아갈 수 있어야 한다(되돌릴 수 없는 감점은 넣지 않는다).

## 4. 진행 구조 (추천안)

- 캠페인 3장, 장마다 페스티벌 4회 = 총 12회(MVP 4~5시간).
  - 1장 동네 페스티벌(1천~3천 명, 무대 1개)
  - 2장 도시 페스티벌(5천~1만 명, 무대 2개, 날씨)
  - 3장 메가 페스티벌(3만~5만 명, 무대 3개, 이틀 일정)
- 장이 바뀔 때만 새 규칙 하나를 더한다(무대 수, 날씨, 이틀).
- 실패: 한 번의 실패는 명성 감소 + 적자. 자금이 바닥나면 게임 오버(해당 장 처음부터 재도전).

## 6. 첫 마일스톤 제안: "페스티벌 한 번" (버티컬 슬라이스)

- 범위: 부지 1곳(32×32), 무대 1개, 시설 6종, 아티스트 8명, 인력 3종, 돌발 카드 3장, 결과 화면 1개.
- 질문: **"한 번 열어보고 바로 한 번 더 열고 싶은가?"** — 프로덕트 오너 플레이 + 봇 통계로 판정.
- 진행 방식(v0 회고 반영): 코드 전에 game-designer가 스프레드시트 시뮬로 루프 수치를 먼저 검증 → 중간에 프로덕트 오너 짧은 플레이 1회 → 완성.

## 7. 프로덕트 오너에게 묻는 것

1. 개최 단계 방식 — 자동 진행 관람 + 돌발 카드(추천) / 즉시 결과 리포트 / 실시간 운영
2. 시설 배치 — 자유 그리드 배치, 시설 8종 내외(추천) / 정해진 구획에 시설 고르기
3. 진행 구조 — 캠페인 3장 × 4회(추천) / 로그라이트 런 / 무한 샌드박스
4. 시작 규모 — 처음부터 야외 페스티벌(추천) / 클럽 공연으로 시작해 페스티벌로 확장
