## 1. v0에서 무엇이 안 맞았나

| 증상 (플레이·봇 통계) | 원인 |
|---|---|
| 건설과 공연이 따로 논다 | 건설은 아무 때나, 공연은 매일 반복. 지은 것이 결과에 **얼마나·왜** 영향을 줬는지 안 보인다. |
| 매일이 비슷하다 (SE-042: 정책마다 등급 1칸) | 같은 클럽, 같은 크기의 공연 반복. "한 번의 큰 승부"가 없다. |
| 처음 10분에 이해할 게 너무 많다 | 첫 판부터 6개 시스템 + 일일 정산·임대료·구제. |
| 결과가 납득되지 않는다 | 만족도가 여러 곱·차의 합성. 실패 이유를 한 줄로 말할 수 없다. |

**교훈**: 시스템 수가 아니라 **"내 결정 → 눈에 보이는 결과 → 이유"의 연결**이 재미를 만든다.

## 2. 게임의 핵심 (한 문장)

> **공연 하나를 기획해 걸고, 그날의 결과를 눈으로 보고, 이유를 배워 다음 무대를 더 크게 연다. 망하면 처음부터, 하지만 더 똑똑하게.**

- 판타지: 무명 프로모터가 동네 클럽 공연에서 시작해 5만 명 메가 페스티벌을 성공시킨다.
- 재미의 원천
  1. **준비의 퍼즐** — 한정된 예산으로 장소·라인업·시설·인력을 맞춘다.
  2. **개최의 긴장** — 내 계획대로 사람이 몰리고, 헤드라이너 순간에 터진다(또는 화장실 줄이 터진다).
  3. **납득되는 성적표** — "화장실 부족 → 대기 30분 → 만족도 −8". 다음에 뭘 바꿀지 바로 안다.
  4. **런의 선택과 재도전** — 매 런마다 다른 기회·아티스트·돌발 상황. 실패해도 해금이 남는다.
- 레퍼런스: Game Dev Tycoon(기획→출시→리뷰 사이클), Slay the Spire(런 구조·다음 칸 고르기·유물), Football Manager 경기일(준비→관람→결과).

## 3. 공연 한 번의 루프 (클럽 5분 ~ 페스티벌 15분)

| 단계 | 플레이어가 하는 일 | 화면 |
|---|---|---|
| ① 제안 | 다음 공연 기회 2~3장 중 하나 선택(규모·위험·보상이 다름) | 카드 선택 |
| ② 준비 | 아래 5가지를 정한다. 시계가 멈춰 있다 | 기획 보드 + 예상치 미리보기 |
| ③ 개최 | 하루가 배속으로 흘러간다. 돌발 카드 2~3장에 선택으로 대응 | 장소 관람 화면 + 실시간 게이지 |
| ④ 결과 | 성공/실패 등급, 숫자 3개, 원인 리뷰 3~5줄 | 성적표 |
| ⑤ 보상 | 자금·명성 반영, 보상 카드 3장 중 1장 선택(넓은 풀·랜덤 등급, 4-1절) → ①로 | 카드 선택 |

**② 준비의 5가지** — 배치가 아니라 **수량·등급·선택**으로 정한다.

| 기둥 | 결정 | 결과에 미치는 영향 |
|---|---|---|
| 장소 섭외 | 후보 장소 중 선택: 수용 인원, 대관료, 특성(음향 좋음/외곽/야외) | 최대 관객, 고정비, 위험 |
| 라인업 | 슬롯에 아티스트 섭외(출연료·집객력·장르), 헤드라이너 | 관객 수, 기대치, 분위기 |
| 시설 | 대여 품목의 수량·등급: 음향 등급, 바·푸드 수, 화장실 수, 의료 부스 | 대기 시간, 매출, 사고 |
| 인력 | 역할별 인원: 보안·바·청소·의료 | 대기열 속도, 사고·쓰레기 |
| 티켓·홍보 | 티켓 가격, 홍보 예산 | 관객 수 vs 1인당 수익 |

준비 화면에는 항상 **예상치 미리보기**(예상 관객, 화장실 1개당 인원, 예산 잔액, 위험 경고 "화장실 부족")가 떠 있다. 개최 전에 이미 "왜"를 볼 수 있어야 한다.

규모가 커져도 **같은 5가지**를 쓴다. 클럽에서는 손잡이가 적고(아티스트 1~2팀, 인력 2종, 시설 2종), 커질수록 손잡이가 하나씩 늘어난다.

**④ 결과의 규칙**: 점수는 3개(관객 수·만족도·수지). 만족도 감점은 원인별로 쪼개서 보여준다. 모든 감점 원인은 ②의 결정 하나로 되돌아갈 수 있어야 한다.

## 4. 런 구조

| 막 | 무대 | 관객 | 공연 수 | 새로 열리는 손잡이 |
|---|---|---|---|---|
| 1막 | 클럽 | 100~300 | 3회 + 막 결산 쇼케이스 1회 | (기본) 장소·아티스트 1~2팀·바·보안·티켓 |
| 2막 | 공연장 | 1천~3천 | 3회 + 결산 공연 1회 | 화장실·푸드, 청소, 홍보 |
| 3막 | 야외 페스티벌 | 1만~3만 | 3회 + 결산 페스티벌 1회 | 무대 2개, 날씨, 의료 |
| 피날레 | 메가 페스티벌 | 5만 | 1회 | 이틀 일정 |

- 런 1회 ≈ 13공연, 60~90분.
- **막 결산 공연**은 관문이다. 목표(예: 만족도 B 이상 + 명성 N)를 못 넘기면 다음 막으로 못 간다.
- **런 실패**: 자금이 0 아래로 떨어지거나 명성이 0이 되면 끝.
- **런 클리어**: 피날레 메가 페스티벌 성공.
- **런 안에서만 유지**: 자금, 명성, 보유 보상 카드(4-1절).
- **런 사이에 남는 것(메타)**: 커리어 포인트로 시작 인맥 카드·아티스트 풀·장소 종류·난이도 해금. MVP에서는 작게.
- 랜덤 요소: 제안 카드, 아티스트 시장, 돌발 카드, 날씨. 시드 고정(재현·봇 통계용).

## 4-1. 보상 카드 (넓은 풀 + 랜덤 등급)

프로덕트 오너 요청(2026-10-20): 보상은 넓은 풀에서 랜덤으로 나오고, 등급이 랜덤으로 갈린다.

**나오는 방식**: 공연이 끝날 때마다 카드 3장이 뜨고 1장을 고른다. 종류와 등급은 각각 따로 굴린다. 같은 런에서 이미 가진 카드는 다시 나오지 않는다. 각 카드는 아래 지속 방식 중 하나다.

- 1회성: 다음 공연에만 적용
- N회: 다음 N번의 공연에 적용
- 런 전체: 런이 끝날 때까지 적용

**종류 (풀)** — MVP는 종류마다 카드 6~10장, 총 50장 내외에서 시작한다.

| 종류 | 성격 | 예시 |
|---|---|---|
| 인맥 | 사람. 런 전체 지속 효과 | 음향 엔지니어 친구(음향 대여비 할인), 지역 기자(홍보 효과 +) |
| 노하우 | 내가 배운 요령. 런 전체 규칙 보정 | 동선 감각(화장실 대기 −), 바 운영 요령(바 매출 +) |
| 섭외 혜택 | 다음 공연 개런티 할인. 1회성·N회 | "다음 공연 헤드라이너 개런티 −20%" |
| 대여 할인 | 장소·장비 대여비 감소. 1회성·N회 | "다음 2회 장소 대관료 −15%" |
| 운영 지원 | 인력·시설 무료 추가. 1회성 | "다음 공연 보안 인원 +2 무료" |
| 즉시 보상 | 자금·명성 즉시 획득 | "후원금 +X", "언론 노출 명성 +Y" |
| 돌발 대비 | 돌발 카드 대응 보조 | "우천 대비 천막: 날씨 감점 1회 무효" |

**등급** — 같은 카드라도 등급이 높으면 효과 폭과 지속이 커진다. 유니크·레전더리는 전용 카드다.

| 등급 | 기본 확률 | 효과 크기(기준) | 특징 |
|---|---|---|---|
| 노멀 (Normal) | 55% | ×1.0 | 기본 수치, 대부분 1회성 |
| 스페셜 (Special) | 25% | ×1.5 | N회 또는 효과 폭 증가 |
| 레어 (Rare) | 13% | ×2.0 | 런 전체 지속이 많아짐 |
| 유니크 (Unique) | 6% | 전용 효과 | 이름 있는 인물·사건 카드, 런당 같은 카드 1장만 |
| 레전더리 (Legendary) | 1% | 규칙을 바꿈 | 예: "헤드라이너 슬롯 +1", "파산 1회 면제" |

- 막이 올라갈수록 높은 등급 확률이 오른다(예: 3막은 노멀 40%).
- 막 결산 공연을 통과하면 레어 이상 1장을 보장한다.
- 성적이 좋으면(등급 A 이상) 3장 중 1장의 등급을 한 단계 올려 굴린다.
- 메타 해금으로 풀에 새 카드가 추가된다(처음엔 노멀~레어 위주, 유니크·레전더리는 해금으로 늘어남).
- 확률·효과 크기는 전부 데이터 테이블(`rewards.json`)에 두고 봇 통계로 조정한다.

## 6. 진행 방식 제안 (v0 회고 반영)

1. **규칙 스펙 + 수치 시뮬** — game-designer가 공연 1회의 수식과 1막 수치를 쓰고, 파이썬 스크립트로 봇 몇백 판을 돌려 "결정이 결과를 바꾸는가"를 먼저 확인한다.
2. **바로 플레이해보는 프로토타입** — 1막(클럽 4공연)을 **브라우저에서 바로 열리는 페이지**로 만든다. 설치·빌드 없이 휴대폰에서도 플레이 가능. 질문은 하나: **"한 막을 끝내고 바로 다시 런을 돌리고 싶은가?"**
3. **Godot 본구현** — 프로토타입에서 확인된 규칙만 옮긴다. 관람 화면의 룩은 이 단계에서 아트 디렉션으로 결정.
