미검출 원인: 가드 없이 `int(1e19)` 는 이 플랫폼(x86)에서 INT64_MIN 이 되고, 그 뒤의 범위 검사(`n_seed < 0`, `ticks_per_second <= 0`)가 어차피 거절한다. 즉 개발자 테스트는 "거절된다"만 보고 "누가 거절했는가"를 보지 않는다. 결과는 플랫폼 정의라, 포화 캐스트(arm64 등)에서는 `int(1e19)` 가 INT64_MAX 가 되어 `ticks_per_second` 검사를 통과할 수 있다. 가드가 유일한 방어선인 곳은 `default_speed`(부호/범위 검사 없음)와 push_error 문구뿐이라 그 둘을 단언한다.

qa 보강 테스트 `project/tests/sim/test_core_as_int_qa.gd`:
- `test_core_has_no_private_as_int`: `res://core/*.gd` 소스에 `func _as_int` 없음(AC2 grep 의 테스트화, 훑은 파일 수 > 3 도 확인).
- `test_tickloop_restore_rejects_1e19_as_not_integer`: `seed`·`tick`·`day`·`tick_in_phase`·`speed` 에 ±1e19 → false, `assert_push_error("숫자 필드")`(범위/I1/I3/I4 문구가 아니라 "정수가 아니다" 경로로 거절됐음을 확인), 상태 해시 불변.
- `test_simconfig_rejects_1e19_default_speed_as_not_integer`: `phases[0].default_speed` ±1e19 → null, `assert_push_error("default_speed 는 정수여야 한다")`.

참고: `time.speed_requested` 경로의 `as_int` 는 버스 E4 가 float 페이로드를 publish 단계에서 거절해 float 가 도달하지 않는다(기존 `test_speed_rejected_keeps_state` 주석). 그래서 속도 요청에서는 2^63 가드를 따로 단언하지 않았다.
