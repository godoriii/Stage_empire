### 구현 판단 평가

- **판단 1 (AC4 판정 조건을 "요청 시안" 기준으로 변경): 타당.** 티켓 문구 `spike.material_id != PLAIN_ID and crowd.material_override == null` 은 같은 티켓의 스파이크 폴백(실패 시 `material_id = PLAIN_ID`)과 결합하면 항상 거짓이라 거부가 발동하지 않는다(실제로 폴백 후 `spike.material_id` 는 plain). 요청 시안(측정기 자신의 `material_id`)을 기준으로 삼고 폴백 여부(`get_material_id() != material_id`)를 OR 한 것은 티켓 의도("라벨은 b 인데 실제 룩은 plain 인 JSON 을 만들지 않는다")를 충족하는 유일한 해석이며, 대조군(plain 은 잘못된 패턴이어도 통과, 정상 b 통과)이 오탐을 막는다. 위 실제 프로세스 실행으로 b·ss 모두 확인. 티켓 AC4 문구와 달라진 점은 결과 절에 기록돼 있어 추적 가능.
