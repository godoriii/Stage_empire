## sim-engineer SE-032 인계 확인 사항

설계자 인계 외에, 이번 QA 에서 직접 부딪히거나 확인한 함정.

- **JSON 숫자는 `float` 로 파싱된다.** GDScript 에서 `JSON.parse_string` 결과의 `footprint`, `cell`, `rotation`, 효과 수치, `tiles` 좌표를 쓰기 전에 `int()` 로 접어야 한다. 스칼라 `assert_eq(405, 405.0)` 은 통과하지만 **`Array` 비교는 `[405] != [405.0]` 로 실패**한다(이번 테스트에서 3건 실제 실패 후 정규화 헬퍼로 해결). `cells`/`sight_blocked_cells` 좌표 배열은 `int` 로 만들어 발행하고, 기대값은 `expected` 에서 읽을 때 정규화 후 비교할 것(BC23).
- **시야 레이는 설계 의사코드와 비트 단위로 같아야 한다.** 출발 = 관람 타일 `t`, 도착 = 초점 `g`(`E[⌊n/2⌋]`, 짝수 길이면 위쪽 가운데), 처음·끝 셀 제외, `e2 >= dz` 가 먼저 x 를 갱신하고 이어 `e2 <= dx` 가 z 를 갱신(대각 걸음 허용). 반대 방향(도착 → 출발)으로 계산하면 41칸이 달라질 수 있다. 차단 셀은 `blocks_sight` 타일(벽·기둥)과 `sight_block` 가구 셀이며 **무대 자신은 제외**.
- **출력 배열 순서**: `viewing_tiles`, `sound_tiles`, `sight_tiles`, `bar_tiles`, `cells`, `sight_blocked_cells` 모두 z 오름차순 → x 오름차순(G6). 기준 데이터의 `sight_blocked_cells` 가 이 순서이고 독립 구현의 결과와 순서까지 같다.
- **정수 나눗셈**: `bp = ⌊count × 10000 ÷ viewing_count⌋`, 수용 `⌊floor_free × 2500 ÷ 10000⌋` 모두 양수라 GDScript `/`(정수 나눗셈) 로 충분. `viewing_count == 0` 은 0.
- **`floor_free`/관람 타일은 도달 집합 `R`(입구에서 4방향 BFS, 점유 셀 통과 불가, `walkable`) 기준.** 입구·완충 타일은 `standing == false` 라 수용·관람에서 빠진다(빈 방 478, 482 가 아님). 철거로 생긴 막힌 구멍은 `R` 밖이라 수용에서 제외된다(D4 설명).
- **B10 (a)/(b)** 는 배치 전후 `R₀`/`R₁` 비교로 구현된다. (a) 는 `R₀ − 새 점유 셀` 이 `R₁` 에 모두 있어야 하고, (b) 는 무대가 있을 때 무대 앞 행 셀 중 `R₁` 에 든 것이 하나라도 있어야 한다(무대 배치 시점에는 "새 무대 포함"으로 판정). BC11~BC13 이 이 세 경우를 덮는다.
