## 발견

1. **SN1 정규식의 `$` 가 끝의 개행 하나를 허용한다 (낮음, 새 티켓 대상).** `^[a-z0-9_]{1,24}$` 는 PCRE 에서 `$` 가 문자열 끝 직전의 `\n` 에도 맞아서 `"a\n"` 이 유효 슬롯이다. 확인: `GameSession.is_valid_slot("a\n")` = true, `"a\n\n"` = false, `session.save_requested {slot: "a\n"}` → `session.saved` 발행, 파일 `a\n.sav` 가 만들어진다. 경로 이탈은 아니다(`/` 와 `.` 은 막힘). 문서(SN1)와 코드가 같은 정규식이라 이 티켓의 AC 위반은 아니고 AC-56e 테스트도 통과한다(테스트는 "문서 == 코드" 만 고정하고 이 틈을 옳다고 보증하지 않는다고 주석에 적었다). 수정은 `\z` 또는 `String.is_valid_...` 식의 직접 검사 + events.md SN1 문구 — game-designer 결정 후 sim-engineer. UI 가 슬롯 이름을 어디서 만드는지는 확인하지 않았다. 재현은 위 한 줄이다. 새 티켓은 producer 가 발행한다(이 qa 의 쓰기 범위 밖이라 파일을 만들지 않았다).
2. 그 밖의 버그 없음.
