- 필수: `docs/reports/perf/SE-013-B.json`, `SE-013-E.json`. 선택: `SE-013-{A,C,D}.json`(표 5행 완성용), dGPU 기기는 `SE-013-{B,E}-dgpu.json`. 하나라도 없으면 그 칸은 "검증 불가"로 두고 결론은 조건부 유지.
- 사람에게 같이 요청: 구성 E 실행 중 화면 캡처 1장(SE-004 캡처와 함께). qa 가 이미지를 읽어 "군중에 그림자 없음, 무대 박스에는 그림자 있음"을 확인한다. 캡처가 없으면 이 항목만 "검증 불가".

### 판정 절차

1. **유효성 검사** (구성마다):
   - 필수 17키 + `gpu_timing_available`·`gpu_timing_note`·`crowd_cast_shadow` 존재, `ticket == "SE-013"`, `run_valid == true`, `run_issues` 빈 배열(이제 예열 10 s·120 프레임·측정 30 s 단축이 자동으로 들어온다), `headless == false`, `vsync == "off"`, `renderer == "forward_plus"`, `resolution == requested_resolution == "1920x1080"`, `godot_version` 4.7.2.
   - `gpu` 가 실제 GPU 이름일 것(`llvmpipe`, `SwiftShader`, `lavapipe`, `Microsoft Basic Render`, 빈 문자열이면 무효).
   - 구성 표: A 5000/32/0, B 5000/32/8, C 5000/32/32, D 10000/32/8, E 5000/32/8. `instance_count_actual`, `shadow_lights_actual` 일치, `instance_mesh_tris` ≤ 800, `shadow_atlas_size` ≤ 2048(전부 2048).
   - **군중 그림자 일치**: B(와 A·C·D)는 `crowd_cast_shadow == true`, E 는 `false`. `crowd_shadows` 가 같은 값. `stage_prop_count_actual == 6`, `stage_prop_tris == 72`.
   - 길이: `warmup_sec ≥ 10`, `warmup_frames ≥ 120`, `measure_sec ≥ 30`, `sample_count ≈ avg_fps × 30`(±5%).
   - `commit` 이 파일들 사이에서 같고 이 브랜치(병합 후라면 병합 커밋)의 해시여야 한다. **SE-003 과 달리 `-dirty` 는 이제 `project/`·`tools/` 의 변경만 뜻하므로 허용하지 않는다**(`-dirty` 면 사람에게 사유를 묻고 코드 변경이 있었다면 재측정). `docs/reports/perf/*.json` 때문에 붙는 `-dirty` 는 더 이상 생기지 않아야 한다. 생기면 측정기 결함 의심으로 버그 티켓 SE-014-bug 에 기록.
2. **통계 재계산**: `avg_fps ≈ 1000/avg_frame_ms`(±0.01), `p1_low_fps ≈ 1000/p1_low_frame_ms`(±0.01), `avg_frame_ms × sample_count ≈ measure_sec × 1000`(±1%), `avg ≤ p1_low ≤ max`(ms). 어긋나면 측정기 버그로 SE-014-bug 부터 티켓.
3. **군중 셰도우 패스 0 확인(AC11 후반)**: E 의 `primitives / (5000 × 708)` 을 계산한다.
   - 기대: 1.0 + UI·바닥·무대 프록시 메인 패스(72 tri)·프록시 셰도우 패스 몫. SE-003 A 실측이 1.0001 이었고 llvmpipe E 는 1.0003 이므로 **≤ 1.001 이면 통과**, 1.001 초과 ~ 1.01 은 수치만 적고 reviewer 에게 문의, **1.01 초과면 군중이 여전히 그림자를 드리운다는 뜻이라 AC11 실패**(`crowd_cast_shadow` 와 모순이면 버그 티켓).
   - B 는 25.0 근방이어야 한다(SE-003 B 실측 88,500,526 → 25.0001). 24.5~25.5 를 벗어나면 B 측정 이상으로 보고 원인을 적는다.
   - 선택 구성 A 가 있으면 `E − A` primitives 가 프록시 몫(수백 tri)인지 확인.
   - `draw_calls` 는 E 가 A 보다 커야 한다(셰도우 패스가 돌았다는 증거). 같거나 작으면 프록시가 셰도우 패스를 못 돌린 것이므로 reviewer 에게 알린다.
4. **GPU 타이밍(AC11)**: `rendering_driver == "vulkan"` 이면 `gpu_timing_available == true` 이고 `bound_hint != "unknown"` 이어야 한다. 어긋나면 측정기 결함으로 SE-014-bug. Metal(M1)이면 `gpu_timing_available == false`, `gpu_timing_note` 에 `metal` 이 있어야 정상이며 `bound_hint == "unknown"` 이면 차분으로 대신한다.
5. **표 채우기**: `project/tests/view/perf/results/SE-013.md` 의 PC 사양 10항목, 구성 행(평균 fps, 1% low fps, 평균 ms, 최대 ms, draw calls, primitives)과 보조 표(primitives 비, `gpu_timing_available`, `bound_hint`)를 JSON 값 그대로 옮긴다(fps 1 자리, ms 2 자리). 기기가 둘이면 표를 기기별로 복사. 쓰기는 qa 범위(`project/tests/`).
6. **관문 판정 한 줄** (수식어 없이 "통과" 또는 "실패"):
   - 기기 구분은 JSON `gpu`/`rendering_driver` 로 한다. dGPU + Vulkan 기기: **E `avg_fps ≥ 60.0`** 이면 통과. Apple M1 / Intel Iris Xe 급 내장 GPU: **E `avg_fps ≥ 30.0`** 이면 통과(ADR-0001 재측정 조건. 측정기 콘솔 `gate.verdict` 는 60 기준이라 M1 에서 "실패"를 찍어도 qa 가 30 으로 다시 판정하고 그 사실을 리포트에 적는다).
   - 두 기기를 다 재면 기기별로 한 줄씩 적는다. 티켓 문구가 "또는"이므로 한 기기라도 자기 기준을 넘으면 AC11 의 숫자 조건은 충족으로 보되, 두 기기의 판정이 갈리면 그대로 병기하고 ADR-0001 상태 줄 갱신은 producer·사람이 판단한다.
   - E 가 기준 미달이면 이 티켓은 결론을 내리지 않고 숫자만 남긴다. 후보 (a) 청크 분할 컬링, (b) `shadow_mesh`, (d) 셰도우 라이트 8 → 4 는 producer 가 새 티켓으로 연다. qa 는 Unity 재검토나 ADR 방향을 제안하지 않는다.
7. **B 대비 개선 비** (참고, 판정 아님): `fps_E / fps_B`, `ms_B / ms_E`, `ms_B − ms_E`(절대 ms). B 가 SE-003 의 B(21.7 fps, 46.06 ms, M1)와 ±10% 안에서 재현되는지 먼저 확인한다(프록시 +72 tri 만으로 달라질 이유가 없다). 벗어나면 기기 상태·열 스로틀링·측정기 경로 변경(`avg_crowd_update_ms` 측정 방식, 위 리뷰어 항목 2)을 의심해 적는다. A 가 있으면 `ms_E − ms_A`(남은 셰도우 비용: 프록시 몫 + 8개 셰도우 라이트 샘플링 비용)도 적는다. llvmpipe 에서 E 가 A 보다 1.75 배 느렸던 점이 실제 GPU 에서도 나타나는지 확인한다.
8. **바운드 분석 단락**: `bound_hint`·`avg_gpu_ms`·`avg_crowd_update_ms`·`avg_render_cpu_ms` 로 SE-003 절차 6 과 같은 방식(85% 기준, 둘 다 미달이면 "원인 미분류")으로 짧게 쓴다. E 가 통과여도 남긴다.
9. **리포트 갱신**: 1~4 가 모두 통과한 뒤에만 이 리포트의 AC11 행과 결론을 "통과"(기기 기준 충족) 또는 "실패"로 바꾼다. 무효 JSON 이 하나라도 남으면 조건부 유지.
10. 최소 사양(Intel Iris Xe 30fps 실기기)은 해당 하드웨어가 없으면 "검증 불가" 그대로 두고, M1 결과를 30fps 급 대리로 쓴다(ADR-0001).
