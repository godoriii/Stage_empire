2. `Time.get_ticks_usec`·`last_advance_usec` 제거, 측정기가 `advance()` 를 감싸 측정: **타당(티켓이 허용한 선택).** view 의 `Time.*` 0건 달성. 확인 사항: `avg_crowd_update_ms` 정의는 `advance()` 한 번의 벽시계 시간으로 SE-003 과 같다. 다만 SE-003 은 스파이크 `_process` 안에서, SE-013 은 측정기 `_process` 에서 재므로 같은 구성이라도 수치가 정확히 같으리란 보장은 없다(qa 는 이 값을 SE-003 과 비교하지 않았다. 실측 후 B 의 값을 SE-003 B 의 6.04 ms 와 비교해 큰 차이가 있으면 측정 경로 차이로 기록). `update_label()` 은 시간 측정 밖에서 호출된다.
3. JSON `ticket` 값/기본 출력 파일명 `SE-013`: **타당, 참고.** 위 관찰 2 참고(SE-004 재사용 시 유의).
4. 무대 프록시를 셰도우 라이트 아래 앞줄에 한 줄로 배치: **타당, AC2 충족 + 테스트로 입증.** 기존 범위 테스트에 더해 qa 보강 테스트(셰도우 Omni 구체와 6초간 계속 겹침)와 llvmpipe 재현(draw calls +72, E−A primitives 640)으로 셰도우 패스가 실제로 돈다는 근거가 있다. **해석 주의(reviewer·producer 용)**: 프록시 6개 × 12 tri 는 실제 게임의 셰도우 캐스터(가구·무대·스태프)보다 훨씬 적다. 따라서 E 의 fps 는 "군중 몫 0, 캐스터 극소"인 **상한 쪽 값**이다. ADR-0001 을 닫는 근거로 쓸 때 이 전제를 명시할 것. 또 프록시와 군중이 화면에서 겹쳐 보이는 것은 의도된 스파이크 전용 배치다(사람 캡처로 육안 확인 예정).
5. 헤드리스·llvmpipe 단축 실행 JSON 이 `user://se013_scratch/` 에 남음: **무관.** 저장소 밖이다. qa 의 실행 결과도 같은 `user://` 아래에 있고 저장소를 오염시키지 않는다.

## 측정 후 절차 (AC11, 사람이 JSON 을 올린 뒤 qa 가 수행)

### 인계 파일

### 판정 절차
