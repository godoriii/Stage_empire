- 입장 수·유형 배분·조기 퇴장·바 방문(8/46/64/28)·`crowd_bp` 는 **네 시나리오 모두 정확히 일치**한다. 차이는 평균 만족에만 있고 최대 6 bp(x 우선 기준 rookie_baseline), z 우선 변형과는 최대 28 bp.

- "경로 동점 때문"의 근거: 같은 독립 구현에서 BFS 방향 순서만 바꿔도(x/rev 계열 vs z/revz 계열) 평균 `wait_bp` 가 38→189(rookie)로 바뀌고 만족이 30 bp 움직인다. 구현의 대기는 price30 에서 두 변형보다 더 작다(4 < 17 < 74) — 즉 대기는 경로 선택에 의존하는 값이지 공식 오류가 아니다. **직접 증명은 아니다**: `AStarGrid2D` 동점 규칙을 복제해 대기 일치를 보인 것은 아니다. 공식 정합은 위 산술과 일치 지표 전체로 확인했다.

## 인계

- **SE-035 (show + reputation)**: `audience.day_summary` 의 `avg_satisfaction_bp`·`crowd_bp`·`avg_components`·`by_type`·`left_early` 를 읽는다. 발행은 공연 마지막 틱(`tick_in_phase == 899`)의 audience `update` 안, 순서 `agent_moved → day_summary → (구독자 연쇄: show.ended …) → sales_reported → close`(`test_au7` 가 고정). `show.ended` 는 `day_summary` 뒤·`day_settled` 앞이어야 한다. `capacity == 0` 일 때 `crowd_bp` 10,000(발견 4)과 `admissions == 0`(요약 `avg 0`)을 show 가 등급으로 접을 때 확인. 입장 0 인 날도 `sales_reported {0,0}` 과 요약이 온다.
- **SE-036 (GameSession)**: ① **SE-034-bug 선행 필수**. ② 시스템 등록은 `register_system("audience", aud.update, aud.snapshot, aud.restore)` 이고 생성자는 `new(config, bus, rng, map: MapConfig)` — `rng` 는 `loop.rng`. ③ 로드 케이스(로드 → 다음 날 저녁)를 30일 리플레이에 포함할 것(수정 전에는 실패해야 정상). ④ 일시정지 로드 시 관객 view 복구(발견 5). ⑤ 스냅샷 `systems.audience` 항목 추가만이고 `snapshot_schema_version` 은 그대로.
- **SE-038 (crowd view)**: `agent_moved` 계약(원소 `[id,px,pz,state,type]` 타입·id 오름차순·gone 1회·0명이면 `agents: []`)이 `test_au7` 로 고정돼 있어 view 테스트가 믿을 수 있다. 낮·close 에는 이벤트가 없다(M7 로 확인) — view 는 낮에 군중을 비워 둘 것.
- **SE-040 (메인 씬 통합)**: 로드 직후 저녁·공연 중이면 다음 틱 전까지 군중이 비어 보인다. 일시정지로 로드하는 흐름이 있으면 SimDriver 가 한 틱을 진행시키거나(허용 시) 복구 경로를 마련할 것. SE-034-bug 가 고쳐지기 전에는 "저장 → 불러오기 → 다음 날" 수동 플레이가 로드하지 않은 진행과 다른 입장 수를 낼 수 있다(눈에 잘 안 띄는 차이: 노이즈 ±10%).
